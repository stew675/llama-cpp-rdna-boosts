# scripts/ — the tooling index

Everything in this directory exists to **apply, regenerate, validate or publish** the delivery.  None of it
is part of the patch set itself.  Each script's header comment is authoritative for its options; this file
is the index.

Conventions: all paths default to this repo (found relative to the script), a `release.json` value is read
for any number the script needs (fork point, tip, tree, block count, hashes) so nothing is hard-coded twice,
and every script is safe to run from any directory.

**Every gate that puts work on the GPU ends with the same fault check**: `check-gpu-faults.sh` scoped to a
timestamp taken **before the gate's first arm** (`--since`), over **every log the gate wrote**, with
`--no-faults` as the only opt-out and a PASS line so a skipped check cannot look like a clean one.  The kernel
journal is shared between runs, so an unscoped check (or a fixed `"N min ago"` window) fails on an earlier
arm's fault — and a window shorter than the gate *misses* its own early arms.  `gate-per-block-build.sh` is the
one exception: it only compiles.  See `TODO` #294's record (`WORKLOG.md` 261108.002).

## The two flows

**Apply + verify (the consumer / developer path)**

```bash
scripts/apply-all.sh /path/to/llama.cpp [this-repo]   # strict 12/12 git am, tree checked vs release.json
scripts/validate-set.sh                               # checksums + a fresh-tarball strict apply (~1 min, no build)
scripts/gate-per-block-build.sh                       # a clean build per block commit (`all`; `--fast` for the release profile)
scripts/gate-prefill-logits.sh                        # prefill-logit KLD gate (prefill changes / every release)
scripts/gate-park-idle-slots.sh                       # server idle-slot parking gate (parking changes / every release)
scripts/gate-hc-fusions.sh MODEL.gguf                 # qwen4exp hyper-connection fusion-equivalence gate (HC changes / every release)
scripts/gate-norm-rows-alias.sh                       # narrow-row norm fusion aliasing gate: driver + real gated GGUF + a SILU-gated hybrid (issues #276 / #285)
scripts/gate-slot-rev-share.sh                          # slot-order sharing gate (issue #291): one rollback index chain per graph instead of one per conv layer, byte-identical text, decode not slower (block 03)
scripts/gate-grid-stall-pad.sh                         # gfx1201 grid-stall pad gate: every covered site pads, matches the CPU reference, text identical with the pad off (issue #277)
scripts/gate-fusion-alias-copy.sh                      # fusion-window leaf-copy gate: a compute-buffer leaf (host-expert scheduler copy) is checked, the repro arm reproduces the unfused chain, text unchanged (issue #287)
scripts/gate-graph-opt-streams.sh                      # GGML_CUDA_GRAPH_OPT stream-layout gate: text identical with the option on, and the copy/branch stream ranges are disjoint by census (TODO #283)
scripts/gate-hc-base-copy.sh                           # hc base-copy pool-lifetime gate: every copy released per statement, one BF16 src1 block per graph, text unchanged (issue #290)
scripts/gate-rebase-release.sh                          # the whole pre-release verdict for a RE-BASE in one command: state, build-per-block, prefill KLD, op suites, coherence texts, host-expert multi-slot DFlash acceptance, real-text prefill, interleaved perf A/B vs the shipped build, GPU faults -> one PASS/FAIL (r236)
scripts/gate-state-pipe.sh                            # batched state save/restore gate (state-path changes / every release)
scripts/gate-ckpt-reuse.sh                            # context-checkpoint reuse gate (checkpoint changes / every release)
scripts/gate-spec-ckpt-device.sh                       # target speculative-checkpoint location gate (server spec-path changes / every release)
scripts/gate-spec-align.sh                            # speculative verify-batch alignment gate, 2/3 GPU + host experts (issue #234)
scripts/gate-spec-width-band.sh                       # speculative verify-WIDTH band gate, band-0 3 GPU, 1/2/4 slots (r185)
scripts/gate-spec-draft-window.sh                      # MTP draft KV window gate, 2 slots over a unified cache (issue #264)
scripts/gate-spec-reuse-window.sh                      # drafter KV reuse gate: the ingest tail vs a partially reused prompt (issue #272)
scripts/gate-kv-window-split.sh                         # the windowed KV across a -sm tensor split, 3/2/1-device + MTP + fit arms (TODO #124)
scripts/gate-kv-residency.sh                             # KV residency gate: the window and the pool, resident arm vs forced-miss arm (campaign P0), incl. a 2-device -sm layer pool section; since r217 it also asserts the pool keeps >= 40 % of the no-pool PROMPT rate (a correct-but-slow placement fails); since r222 it also gates the provider's selftest (PASS by default, FAIL without the quarantine hold)
```

**Release work (assessing PRs, A/B arms, the folded tree): ONE checkout, never one worktree per arm**

```bash
scripts/scratch-tree.sh init                     # the scratch tree at the fork point (~/llama-scratch)
scripts/scratch-tree.sh blocks                   # the 14-block delivery tree, built
scripts/scratch-tree.sh arm /tmp/pr218/0014*.patch   # release tree + one PR patch, rebuilt (a delta)
scripts/scratch-tree.sh keep base                # copy build/bin aside for an A/B against a later state
scripts/scratch-tree.sh gate --changed-from <prev-tip>   # per-block gate, reusing this path's ccache
```

**Cut a release (the maintainer path)**

```bash
scripts/make-patches.sh        # re-export the blocks from the canonical fork chain (git format-patch)
scripts/make-release.sh        # rewrite release.json + rdna-boosts-all.patch, hashes included
scripts/validate-set.sh        # must be green before the tag
git tag v<blocks>-<base>-r<N> && git push origin main --tags
# then the worker builds and pushes the container images (see CONTAINERS.md)
```

| `apply-all.sh` | Applies the whole set to a clean llama.cpp checkout: refuses a dirty tree or an existing `rdna-boosts` branch, applies all blocks with **strict `git am`** (one commit each), retries the series once with `git am -3` on drift, and on the strict path asserts the applied tree equals `release.json.tree` and prints the applied **tip** (deterministic: committer identity pinned to the series author, committer date = author date). `--include-optional` then steps through `optional/*/*.patch` on top of the verified tree asking `[y/N]` per artifact (default `N`; it reads the controlling terminal, and refuses to guess when there is none) and applies the accepted ones with strict `git am` (an optional artifact is cut against exactly that tree, so no 3-way merge), while `--include-optional-all` applies every one without prompting for a scripted/headless apply, and `--include-beta` then applies `beta/*/*.patch`; with either flag the checkout is *not* the release tree. | applying the delivery; the only supported apply flow (`git apply` on the concatenated series drops hunks) |
| `fork-refresh.sh` | The release-time fork refresh, mechanical: checks the checkout is clean and has `release.json.base`, leaves the branch, deletes `rdna-boosts`, runs `apply-all.sh`, asserts the applied **tree** equals `release.json.tree` and the commit count equals `n_blocks`, and prints the applied **tip** (the value `release.json.tip` must carry). `--build` builds the branch, `--gates` runs the coherence + prefill-logit gates (and prints the MTP Protocol A command), `--push` force-with-leases the branch to the **personal fork only** (the remote url is checked against an allow-list; upstream is not reachable from this script). **Printed tip is reproducible:** `apply-all.sh` pins the committer identity to the patch series' author and stamps each commit's committer date from its own author date, so the same base + patches give the same commit ids on any machine. | every release (AGENTS "Pushing policy"), and whenever the block set changes; the `.tip` rule is in `AGENTS.md` |
| `validate-set.sh` | The cheap gate that runs on every push: every `patches/*.patch` and `rdna-boosts-all.patch` matches its recorded sha256; the set applies strictly on a **fresh codeload tarball** of `release.json.base`; the base tree and the applied tree/commit count equal what `release.json` records. No compiler, no Docker, ~1 minute. | before every push/tag (CI runs it) |
| `validate-gpu.sh` | The **heavy CI gate** for the off-host worker (`radiance`, gfx1151): materialises the set from scratch at a rev (default `origin/main`), asserts the applied tree == `release.json.tree`, runs `gate-per-block-build.sh --fast`, builds the tip's test binary and runs the seven op oracles, then `gate-prefill-logits.sh` (recording a base on a fresh box, comparing afterwards) and, when the applied tree touches a GDN conv fold or its device gate, `test-logits-width-probe` at `P=3584`/`P=4096` in a single-device arm **and** the `-sm tensor`/`-sm layer` arms the box can run (step 4c: the fused arm must be run-to-run stable, bit-identical to `GGML_CUDA_DISABLE_CONV_FUSION=1`, and must actually log `snap=1` while the reference arm logs no direct conv at all — a fold is a launch-order change, which only a cross-run instrument sees, and since r186 the multi-device arms are the ones that can regress). Auto-detects `/opt/rocm-10.1.0-gfxNNNN`. `flock`-serialised, skips while a container build runs, per-rev attempt cap, per-run summaries pruned to `KEEP_RUNS`. `SKIP_LADDER` / `SKIP_OPTESTS` / `SKIP_KLD` / `SKIP_HC` / `SKIP_GDN_WIDTH` narrow a run. | every new `origin/main` commit (cron on the worker); by hand with a rev after a risky merge |
| `gate-per-block-build.sh` | Builds the target set **once per block commit** from a wiped build directory (a reused cache hides configure/header errors and reports a wrong list). `--changed-from <rev>` rebuilds only the blocks whose delta changed (the tip is always built), `--list-only` prints the matrix, `--fast` builds the release profile (libraries + shipped binaries, no tests/tools) instead of `all`. **Measured (r138): a re-base ladder is 2101 s cold / 95 s warm with `all` and 78 s warm with `--fast`; the cold difference is `tests/test-backend-ops.cpp` at 5m13s per distinct content (~4 per re-base).** | before a release, and after moving a fix between blocks |
| `scratch-tree.sh` | **The release-arm driver: one long-lived worktree + build dir, switched between states** (`init`, `state REV`, `blocks`, `arm PATCH...`, `tip`, `keep TAG`, `gate`, `show`). | `gate-ckpt-reuse.sh` | The context-checkpoint reuse gate (r155, PR #236, `LLAMA_SERVER_CKPT_REUSE`). The gate drives a long prompt plus three resumptions in the two arms and **fails** unless every request's greedy text is byte-identical, the keep arm kept a restored checkpoint and superseded none while the eager arm did the opposite, the keep arm created fewer checkpoints, and no arm aborts or faults a GPU. On a recurrent/hybrid target the server saves the target's recurrent state before a verify whose draft is longer than `n_rs_seq`, and restores it on a partial acceptance; r184 keeps that checkpoint in device memory (one staging buffer per slot) instead of host memory when one GPU has room.  **The device arm is not a byte image**: `data_tgt` holds only the metadata while the payload lives in the context's per-seq staging buffer, so a restore whose save it does not match is a SILENT wrong answer - and nothing else in the repo reaches this code (`tests/test-llama-context`'s `cp_d` covers the io class, not the server's use of it, and `gate-ckpt-reuse.sh` covers a different object). The `-nkvo` arm is excluded from the text comparison on purpose (moving the KV cache off the GPU selects different kernels by itself).  **SKIPs** when the device path is not reachable (multi-GPU split, state too large for state + 512 MiB, or no checkpoint taken). | `gate-state-pipe.sh` | The batched state save / restore gate (`LLAMA_STATE_ASYNC`, `LLAMA_STATE_ASYNC_READ`, `LLAMA_STATE_PIPE_GROUPS`, `LLAMA_STATE_COPY_THREADS`). | `gate-park-idle-slots.sh` | The server idle-slot parking gate (issue #210 / PR #225 / issue #227). | `gate-norm-rows-alias.sh` | The **narrow-row norm fusion aliasing** gate (r225, issue #276).  `ggml_cuda_norm_rows_try_fuse()` fuses `RMS_NORM -> MUL(w)` on narrow rows and, for the sigmoid-gated form (`RMS_NORM -> MUL(w) -> MUL_MAT -> SIGMOID -> MUL`, the qwen4exp / bailingmoe3 per-head gate), it dispatches the gate `MUL_MAT` **itself** before the fused launch.  In graph order `x` is dead as soon as the `RMS_NORM` has consumed it and the gate output has exactly `x`'s shape, so the allocator's best fit for it is `x`'s own block: the pre-dispatch then writes the gate output over the activation the fused kernel has not read yet.  The delivery is safe only because `ggml_backend_cuda_graph_optimize` keeps `x`/`w`/`z` alive until the fused output (alloc deps, in a different file, documented there as a buffer-size trade), and a caller that computes this graph **without a scheduler** has none of them.  **Section A** drives the backend directly (`scripts/norm-rows-alias.cpp`, `ggml_backend_graph_compute()`, so no deps exist) on the gated shape and forces each aliasing shape by pointing a tensor at another's buffer after allocation, inside one arena with a row of slack (an out-of-arena pointer would be a write past the block, not an aliasing test): `alias_gate` (gate output == `x`) and `alias_dst_row` (fused output == `x` + 1 row) must be **declined**, `alias_dst_exact` (fused output == `x` exactly: a read-then-write of the same address by the same thread) must still **fuse**, and every arm must reproduce `ref` byte for byte and match the driver's own `--no-fuse` digest (so the fused launches are also proven bit-identical to the chain at this shape).  **Section B** drives the delivery path on a real gated GGUF (Ling-3.0-tiny IQ4_NL, `-c 8192` over the 5256-token `prompts/prose-rdna-boosts.txt`) and fails unless the gated form **fused** (>= 1 `fused=1 gated=1` line: otherwise the text comparison is vacuous), **declined nothing** (the scheduler's alloc deps still hold `x`/`w` -- the one assertion that catches a dropped or renumbered dep, which is silent because the guard falls back), the fused arm's text equals `GGML_CUDA_DISABLE_NORM_ROWS=1`, and neither arm aborts or faults a GPU.  **Section C** is the GitHub-issue-#285 arm, on a **SILU**-gated hybrid (Qwen3.5-4B Q8_0, `qwen35`): same two armed runs at `-c 8192`, and it fails unless the PLAIN form fused (`>= 1` `fused=1 gated=0`), **declined nothing**, and the text equals the kill-switch arm.  A SIGMOID-gated model cannot test that path (its gated match succeeds), which is why section B alone passed before and after the fix.  **Negative-tested (r225)**: with the guard removed the driver's `alias_gate`/`alias_dst_row` digests are `bed78b1da3ac9b28`/`2b0800ea70a3eb6a` against a `bcc36422f9a120ac` reference; with the `x -> dst` alloc dep dropped, Ling's 32-token greedy text collapses from 172 chars (`f476efaac086`, identical to the unfused chain) to 52 and section B fails on both assertions.  **Negative-tested (r238)**: the pre-#285 build fails section C with 264 `declined=gate-out` lines on the Qwen3.5-4B arm (80 plain fusions out of 344 decisions) and passes it with 344/344 plain fusions and 0 declines after the fix.  `MODEL_ARM=0` runs the driver only; `C_ARM=0` / `SILU_MODEL=` skip the SILU arm. Nine arms on one pool-backed host-expert config, same-seed greedy: shipped / `MOE_HOST_POOL_DIO=1` / `MOE_HOST_POOL_DIO_FAULT=1` (a platform with NO disk tier) / `MOE_HOST_POOL_FILL_FAULT=1` (no source can be resolved at all) / `MOE_HOST_POOL_FILL_FAULT=late` (each table gets one source, then loses it -- the mid-run shape, r223) / `MOE_HOST_POOL_SINK=1` (the demote) / `MOE_HOST_POOL_SINK=1 MOE_HOST_POOL_SINK_FAULT=1` (every demote copy fails) / `MOE_HOST_POOL_PIN_FAULT=late` (r229) / `MOE_HOST_POOL_PIN=0` (r233).  **Fails** unless every text is byte-identical (except the documented `pinlate` mixture), the three healthy arms build a real pool (slots > 0, MiB pinned > 0) with no fill failure, `nodisk` is not vacuous (the refusal is logged), and the two failure arms stay CORRECT with `FAILED fills: N` in the census, `the slot is NOT resident` per table and **`takeover=0`** (r223: the call that fails a fill must decline, or `moe_cache_get_table` refuses the table a few lines later while the scheduler already skipped the `input_cpy` copy), and (r227) **every arm prints the exit census exactly once and from the MODEL TEARDOWN** (`host pool (L2)` before `model teardown: dropped`): `moe_cache_report` is an `atexit` hook inside ggml-hip.dll, so on Windows it runs after `main` has returned and llama-server's async log is already gone, which is why the reporter's clean Ctrl+C showed every teardown line except the census.  Model/gpu/flags are environment (`LLAMA_CLI`, `MODEL`, `GPU`, `CTX`, `UB`, `NCMOE`, `LIMIT_FRAC`, `PROMPT`, `PROMPT_FILE`, `NGEN`, `EXTRA_ARGS`, `KEEPOUT`); ~3 min on one GPU (5 `llama-cli` starts, pool prewarm dominates). | any change to the pool's fill/staging, `expert_host_src()`, `access_locked()`'s admission, the `-lme`/`--host-experts pool` placement, the loader's host-expert source registration, or the exit census; every release |  **Since the host-expert-split campaign the gate also runs two demote arms** (`MOE_HOST_POOL_SINK=1` and `MOE_HOST_POOL_SINK=1 MOE_HOST_POOL_SINK_FAULT=1`): the first proves the arm reaches the demote at all (it must demote), and the second proves the issue-#274 rule holds for it -- every demote copy failing must **decline** the demote (`0 demoted`, `copy-error` declines > 0) and never publish a victim slot, because a published victim would serve stale bytes for the life of the run.  Both must be byte-identical to `ref`.  Every arm runs with `MOE_EXPERT_HEATMAP=load` so the nine arms are compared across one prior (a writable map is rewritten per run).  **(r229, issue #278) an eighth arm `pinlate` (`MOE_HOST_POOL_PIN_FAULT=late`) latches the pinned tier off after the pools and the arena exist** -- the Windows shape at the adapter's aperture ceiling -- and asserts that the latch stops the tier GROWING rather than discarding the pinned memory the run already owns: the census must report `N expert fills were served from a host pool built BEFORE the refusal` with N > 0 (measured 7 060 with the fix against 0 with the lookup back after the guard, which also turns 110 failed fills into 1 587), the pools must exist before the latch, and the text must not move.  **(r233) a ninth arm `pin0` (`MOE_HOST_POOL_PIN=0`) closes the pinned tier from the start** -- the arm for a Windows box stuck on the driver-shipped HIP runtime (issue #278) -- and asserts no host pool is built, the census names the switch, and the greedy text is byte-identical to `ref`. ## Notes

* **`release.json` is the only source of truth** for the fork point, tip/tree, block count and hashes.
  `apply-all.sh`, `fork-refresh.sh`, `validate-set.sh`, `make-patches.sh`, `make-release.sh`, `build-containers.sh`,
  `container-watch.sh` and CI all read it; if a script disagrees with the manifest, the manifest wins.
* **Order matters on a release:** `make-patches.sh` → `fork-refresh.sh` (re-cut; it prints the tip to
  record) → `make-release.sh --tip <printed>` (+ `--tree`, which `fork-refresh.sh` also prints) →
  `validate-set.sh` → commit → tag.  A tag cut before `make-patches.sh`/`make-release.sh` ships a
  manifest that does not match `patches/`, and a tag cut before the fork refresh ships a stale branch.
  **`--tip` is always the fork branch tip that `fork-refresh.sh`/`apply-all.sh` printed, never the tip of
  the working chain in `~/llama.cpp`** (same tree, different commit id); the rule is in `AGENTS.md`.
* **The gates are not interchangeable.**  Coherence (same-seed text) is blind to a uniform prefill shift;
  the prefill-logit gate is blind to decode drift; MTP is blind to both.  `MANIFESTS.md` lists which gate a
  given block needs.
* **Run GPU gates alone.**  Two concurrent GPU jobs change the arena/band layout and invent failures.
* `--help` on any script prints its header comment (the option list) without running anything.
