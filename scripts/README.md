# scripts/ — the tooling index

Everything in this directory exists to **apply, regenerate, validate or publish** the delivery.  None of it
is part of the patch set itself.  Each script's header comment is authoritative for its options; this file
is the index.

Conventions: all paths default to this repo (found relative to the script), a `release.json` value is read
for any number the script needs (fork point, tip, tree, block count, hashes) so nothing is hard-coded twice,
and every script is safe to run from any directory.

## The two flows

**Apply + verify (the consumer / developer path)**

```bash
scripts/apply-all.sh /path/to/llama.cpp [this-repo]   # strict 12/12 git am, tree checked vs release.json
scripts/validate-set.sh                               # checksums + a fresh-tarball strict apply (~1 min, no build)
scripts/gate-per-block-build.sh                       # a clean build per block commit (`all`; `--fast` for the release profile)
scripts/gate-prefill-logits.sh                        # prefill-logit KLD gate (prefill changes / every release)
scripts/gate-park-idle-slots.sh                       # server idle-slot parking gate (parking changes / every release)
scripts/gate-hc-fusions.sh MODEL.gguf                 # qwen4exp hyper-connection fusion-equivalence gate (HC changes / every release)
scripts/gate-state-pipe.sh                            # batched state save/restore gate (state-path changes / every release)
scripts/gate-ckpt-reuse.sh                            # context-checkpoint reuse gate (checkpoint changes / every release)
scripts/gate-spec-ckpt-device.sh                       # target speculative-checkpoint location gate (server spec-path changes / every release)
scripts/gate-spec-align.sh                            # speculative verify-batch alignment gate, 2/3 GPU + host experts (issue #234)
scripts/gate-spec-width-band.sh                       # speculative verify-WIDTH band gate, band-0 3 GPU, 1/2/4 slots (r185)
scripts/gate-spec-draft-window.sh                      # MTP draft KV window gate, 2 slots over a unified cache (issue #264)
scripts/gate-spec-reuse-window.sh                      # drafter KV reuse gate: the ingest tail vs a partially reused prompt (issue #272)
scripts/gate-kv-window-split.sh                         # the windowed KV across a -sm tensor split, 3/2/1-device + MTP + fit arms (TODO #124)
scripts/gate-kv-residency.sh                             # KV residency gate: the window and the pool, resident arm vs forced-miss arm (campaign P0), incl. a 2-device -sm layer pool section; since r217 it also asserts the pool keeps >= 40 % of the no-pool PROMPT rate (a correct-but-slow placement fails)
```

**Release work (assessing PRs, A/B arms, the folded tree): ONE checkout, never one worktree per arm**

```bash
scripts/scratch-tree.sh init                     # the scratch tree at the fork point (~/llama-scratch)
scripts/scratch-tree.sh blocks                   # the 14-block delivery tree, built
scripts/scratch-tree.sh arm /tmp/pr218/0014*.patch   # release tree + one PR patch, rebuilt (a delta)
scripts/scratch-tree.sh keep base                # copy build/bin aside for an A/B against a later state
scripts/scratch-tree.sh gate --changed-from <prev-tip>   # per-block gate, reusing this path's ccache
```

**Cut a release (the maintainer path)**

```bash
scripts/make-patches.sh        # re-export the blocks from the canonical fork chain (git format-patch)
scripts/make-release.sh        # rewrite release.json + rdna-boosts-all.patch, hashes included
scripts/validate-set.sh        # must be green before the tag
git tag v<blocks>-<base>-r<N> && git push origin main --tags
# then the worker builds and pushes the container images (see CONTAINERS.md)
```

| `gate-kv-residency.sh` | The **KV residency** gate (r206, `wip/kv-residency-cleanup/` §2.1 = the archive plan's phase **P0**): block 15's two placements, each with a resident arm and a **deliberately under-sized** one, because a residency defect is a wrong answer, not a crash.  **Window** (4B, `-c 16384` f16, 5 246-token prompt): `wref` (no knob), `wres` (`W=8192`, above the run depth), `wspill` (`W=2048`, far below) — the text must be byte-identical on all three, `wres` must never flip a mapping nor map a host byte, and `wspill` must do both (`FLIP device 0` > 0, `of which host` > 0).  **Pool** (Flash-Next GSQ-IQ3_XXS + MTP sidecar, 1 GPU, `-ncmoe 48`, q8_0, `-c 32768`, 25 763-token prefix, `-n 64`, MTP depth 4): `pref` (no pool, the SPARSE arm the pool replaces), `pres` (`LLAMA_KV_REGION_POOL=32768` = the whole cache), `pfloor` (`LLAMA_KV_REGION_POOL=512`, FLOORED to one decode band, with `LLAMA_KV_POOL_VERIFY=1`) — text and `draft_n`/`draft_n_accepted` identical across all three, `bad 0`, claims/resolves/hits all non-zero, `pres` holding exactly `-c/4` pages while `pfloor` holds fewer, and on the **same** resolve count `pfloor` claiming more per resolve and hitting less (the two arms must NOT report the same residency — a gate that cannot leave the resident arm is not a gate). | `apply-all.sh` | Applies the whole set to a clean llama.cpp checkout: refuses a dirty tree or an existing `rdna-boosts` branch, applies all blocks with **strict `git am`** (one commit each), retries the series once with `git am -3` on drift, and on the strict path asserts the applied tree equals `release.json.tree` and prints the applied **tip** (deterministic: committer identity pinned to the series author, committer date = author date). `--include-optional` then applies `optional/*/*.patch` on top of the verified tree (strict `git am`; an optional artifact is cut against exactly that tree, so no 3-way merge), and `--include-beta` then applies `beta/*/*.patch`; with either flag the checkout is *not* the release tree. | applying the delivery; the only supported apply flow (`git apply` on the concatenated series drops hunks) |
| `fork-refresh.sh` | The release-time fork refresh, mechanical: checks the checkout is clean and has `release.json.base`, leaves the branch, deletes `rdna-boosts`, runs `apply-all.sh`, asserts the applied **tree** equals `release.json.tree` and the commit count equals `n_blocks`, and prints the applied **tip** (the value `release.json.tip` must carry). `--build` builds the branch, `--gates` runs the coherence + prefill-logit gates (and prints the MTP Protocol A command), `--push` force-with-leases the branch to the **personal fork only** (the remote url is checked against an allow-list; upstream is not reachable from this script). **Printed tip is reproducible:** `apply-all.sh` pins the committer identity to the patch series' author and stamps each commit's committer date from its own author date, so the same base + patches give the same commit ids on any machine. | every release (AGENTS "Pushing policy"), and whenever the block set changes; the `.tip` rule is in `AGENTS.md` |
| `validate-set.sh` | The cheap gate that runs on every push: every `patches/*.patch` and `rdna-boosts-all.patch` matches its recorded sha256; the set applies strictly on a **fresh codeload tarball** of `release.json.base`; the base tree and the applied tree/commit count equal what `release.json` records. Prints each build's wall time. | assessing PRs, beta arms, A/B builds, and any per-release build work |

| `gate-ckpt-reuse.sh` | The context-checkpoint reuse gate (r155, PR #236, `LLAMA_SERVER_CKPT_REUSE`).  A hybrid/recurrent server restores a context checkpoint and then re-saves the identical state at the same position before its first batch; r155 keeps it instead and recycles the buffers of dropped checkpoints.  The gate drives a long prompt plus three resumptions in the two arms and **fails** unless every request's greedy text is byte-identical, the keep arm kept a restored checkpoint and superseded none while the eager arm did the opposite, the keep arm created fewer checkpoints, and no arm aborts or faults a GPU.  It **SKIPs** when the config makes no usable checkpoint or the keep path is unreachable (a dense/SWA target restores at `pos_max` = `n_tokens - 1`, so nothing is re-saved at the same position; only a hybrid/recurrent memory reports `pos_min == pos_max`).  **No other gate reaches this code**: no other gate restores a context checkpoint, and the failure mode is a wrong answer on the *next* resume, not a crash. | `gate-spec-ckpt-device.sh` | The target speculative-checkpoint location gate (r184, PR #254, `LLAMA_SERVER_SPEC_CKPT_DEVICE`).  On a recurrent/hybrid target the server saves the target's recurrent state before a verify whose draft is longer than `n_rs_seq`, and restores it on a partial acceptance; r184 keeps that checkpoint in device memory (one staging buffer per slot) instead of host memory when one GPU has room.  **The device arm is not a byte image**: `data_tgt` holds only the metadata while the payload lives in the context's per-seq staging buffer, so a restore whose save it does not match is a SILENT wrong answer - and nothing else in the repo reaches this code (`tests/test-llama-context`'s `cp_d` covers the io class, not the server's use of it, and `gate-ckpt-reuse.sh` covers a different object).  Three arms, one binary: host (`=0`), device (default) and `-nkvo`.  **Fails** unless the device arm took the device path and really created checkpoints, the kill-switch arm never did, the `-nkvo` arm takes the host path with its own `state is not offloaded` reason, every request's greedy text plus the drafted/accepted counts are byte-identical between the host and device arms, and no arm aborts or faults a GPU.  The `-nkvo` arm is excluded from the text comparison on purpose (moving the KV cache off the GPU selects different kernels by itself).  **SKIPs** when the device path is not reachable (multi-GPU split, state too large for state + 512 MiB, or no checkpoint taken).  It also prints per-arm t/s, the created/restored checkpoint counts and the RSS delta.  Model/binary/flags are environment (`MODEL`, `DRAFT`, `SPEC_TYPE`, `COPY_FILE`, `CTX`, `NGEN_COPY`, `NGEN_PROSE`, `NGPU`, `NCMOE`, `PORT`, `EXTRA_ARGS`, `KEEPOUT`); ~4 min on one GPU (27B, 3 server starts). | any change to the server's speculative checkpoint path (`spec_ckpt*`, `use_ckpt_tgt`, the state io classes' use there), `LLAMA_SERVER_SPEC_CKPT_DEVICE`; every release |
| `gate-state-pipe.sh` | The batched state save / restore gate (`LLAMA_STATE_ASYNC`, `LLAMA_STATE_ASYNC_READ`, `LLAMA_STATE_PIPE_GROUPS`, `LLAMA_STATE_COPY_THREADS`). | `gate-park-idle-slots.sh` | The server idle-slot parking gate (issue #210 / PR #225 / issue #227). Drives one 4-request sequence — a long prompt on slot 0, a short one on slot 1, a return to slot 0 (unpark), a launch on slot 2 — in three arms (`park`, `LLAMA_SERVER_PARK_IDLE_SLOTS=0`, `LLAMA_SERVER_LAZY_IDLE_SLOTS=0`) and **fails** unless (a) no arm aborts, (b) the parking arm really moved cells (`LLAMA_KV_PARK_DEBUG=1` traced both a park and an unpark, and no park was refused because the indexer cache did not mirror the attention cache) **or** every park was legitimately declined — the server logged *"cannot park the idle slot: saving it to the prompt cache and clearing it"*, which is what a region-backed/windowed KV produces and what a slot whose cells are not one run already did, and which the gate reports as *"parking declined -> save-and-clear fallback"* (it counts **moves**, not lines: the region refusal warning is logged under the `seq_park` prefix too) — and (c) the parking arm is byte-identical to lazy-off on **every** request. Model/binary/ctx/flags are environment (`MODEL`, `LLAMA_SERVER`, `SM`, `NCMOE`, `NGPU`, `CTX`, `NGEN`, `PORT`, `EXTRA_ARGS`); ~1.5 min on 3 GPUs. It is inert in `llama-cli`/`llama-bench`/`llama-perplexity`, so no other gate reaches the park path. | any change to the park API, a memory type that carries a second cache, or the server's park scheduling; every release (it is the only gate that exercises `llama_memory_seq_park` end to end) |
| `gate-hc-fusions.sh` | The qwen4exp hyper-connection fusion-equivalence gate (issue #228). `build_hc_mix`/`build_hc_combine` each exist twice — as a plain ggml chain (the model's definition) and as a fused op (`GGML_OP_HC_MIX` / `GGML_OP_HC_COMBINE`) — and `LLAMA_FUSED_HC_MIX` / `LLAMA_FUSED_HC_COMBINE` select them **independently**, so there are four arms; this runs all four (plus the CUDA-side chain fusions and the DSV4 HC pre/post pair) on a real GGUF and **fails unless every hard arm reproduces the unfused chain byte for byte**.  The DSV4 HC pre/post pair is **reported, not hard** (r156): those ops own the HC16 bf16 producer slots and are a documented numeric re-baseline, so the `PRE`/`POST` knobs swap producer precision as well as the fusion (IQ4_NL class: mean KLD 0.021542 / 95.814 % vs the chain, printed as `reported`; a *change* in that magnitude is the signal, and on the BF16-hc class they still match byte for byte). It exists because `test-backend-ops` checks each op against a CPU reference that can share the op's mistake (through r147 the fused mixer published a raw inject logit and the fused combine divided it by `hc` again: two of the four arms were wrong, silently, for ten releases — a Q5_K requant collapsed and a BF16-hc model produced an empty generation with `LLAMA_FUSED_HC_COMBINE=0`). **Run it once per hc-down weight class** (`--types MODEL.gguf` prints the class: Q8_0/BF16 take the fused mixer, anything else the chain). `FUSED`/`REPORTED` arms, `EXTRA_ARGS`, `NGEN`, `CTX`, `MODEL` are environment. | before changing an HC op, its chain or a matcher; every release |
| `gate-spec-align.sh` | The speculative verify-batch alignment gate (issue #234).  `llama_memory_hybrid::init_batch()` splits a decode with `split_equal()`, which stops at the shortest sequence set, so two slots verifying **different draft lengths** put the longer one's tail into a second ubatch and the target runs twice for that step.  The fixed `--spec-draft-n-max` path never produced a difference; `draft-mtp-adaptive` holds a per-sequence depth, so on a multi-slot server it is the normal case.  The gate drives a two-slot server (`--parallel 2 --kv-unified`) with a high-acceptance and a low-acceptance prompt and **fails** unless the concurrent pair recovers >= `RECOVER` (default 10 %) with `LLAMA_SPEC_ALIGN` on, the equal-length arm (two identical prompts) does not regress beyond `REGRESS` (default 10 %, a coarse bound: the adaptive controller's transient makes this arm spread ~12 % between two identical runs), every **single-slot** request's greedy text is byte-identical on/off, the `n_seq == 1` `llama-cli` text is byte-identical (and matches `REF_HASH` when set), the alignment arm actually split decode steps while the aligned arm splits none (the recurrent memory's `RSPREP prep=1/N` trace, with a single-row ubatch excluded: a slot that drafted nothing has no length to align), and no arm aborts with no GPU fault.  It runs at **2 and 3 GPUs** plus a host-expert `-ncmoe` arm because the penalty scales with the devices the duplicated pass spans, and a **mixed-drafter** arm (`ngram-mod,draft-dflash` + a DFlash2 draft, `MIXED_ARM`, `DRAFT_MIXED`, `PROMPT_B_MIXED`) that must stay within 2 % of its knob-off self with identical draft counts: r153's generic `min` cut shipped a -6 % regression on that chain and only that arm could see it.  The two-slot pair's text divergence point is reported, not gated: the two arms are two **configs** (a different verify width), each of which is deterministic run to run, and the rulebook promises greedy text per config (`GREEDY-PURITY.md` §63).  Model/prompts/spec/flags are environment (`MODEL`, `NCMOE_MODEL`, `PROMPT_A`, `PROMPT_B`, `PROMPT_B_NCMOE`, `SPEC`, `NMAX`, `NGEN`, `NGPU`, `SM`, `NCMOE`, `CTX`, `RECOVER`, `REGRESS`, `REF_HASH`, `PORT`, `EXTRA_ARGS`, `KEEPOUT`); ~12 min for the default 2/3 GPU + host-expert set. | any change to `common_speculative_draft()`, a drafter's per-sequence depth or the hybrid ubatch split; every release |
| `gate-spec-width-band.sh` | The speculative verify-**width** band gate (r185, `LLAMA_SPEC_ALIGN_WIDTH_BAND`).  `align_draft_caps()` bounds the aligned draft depth so one verify batch stays inside one kernel family; the bound it had was the expert-cache band, which r176 made answer only for a model with host-resident experts -- so on a **band-0** config (all-in-VRAM, `-sm layer`, no routed expert) a multi-slot `draft-mtp-adaptive` draft was **unbounded**, and 4 slots at `--spec-draft-n-max 7` present ~28-32 rows.  `LLAMA_SPEC_ALIGN_WIDTH_BAND` (default 16, `0` = off) supplies the width where there is no arena; the arena band still wins where there is one.  The gate drives a band-0 3-GPU server (`--parallel` 1, 2 and 4) on one binary and **fails** unless: the bound really fires on the 4-slot arm (`aligned draft depth ... -> 3` with `width band 16`) and never on the knob-off arm, the 4-slot aggregate is >= `RECOVER` (default 10 %) of the knob-off arm, the 1- and 2-slot arms are inert (no bound line at all, byte-identical text, within `REGRESS` 3 %), every arm generated its full token budget, and no arm aborts with no GPU fault.  **No other gate reaches this code**: the coherence, prefill-logit and four-axis MTP protocols run ONE sequence (16 / 1 - 1 = 15 is above any `n_max`) and `gate-spec-align.sh` runs two or fewer on arms whose depth is at or below 7 -- this is a four-slot property, which is why it went unseen until PR #169's numbers were re-measured on r184 (+14.2 to +31.8 % on three shapes).  Model/flags are environment (`MODEL`, `GPUS`, `SM`, `SPEC`, `NMAX`, `NGEN`, `CTX`, `RECOVER`, `REGRESS`, `WIDTH_BAND`, `PORT`, `EXTRA_ARGS`, `KEEPOUT`); ~5 min on 3 GPUs (6 server starts). | any change to `align_draft_caps()`, its band/width inputs or `LLAMA_SPEC_ALIGN_WIDTH_BAND`; every release |
| `gate-spec-draft-window.sh` | The MTP draft **KV window** gate (r200, issue #264, `LLAMA_SPEC_DRAFT_WINDOW`).  The draft context's KV is a sliding window, and under `--kv-unified` that one cache holds every sequence, so it must be sized PER SEQUENCE -- `(win + one batch) x n_seq_max` cells via `llama_spec_draft_kv_cells()`, the same function the slab's draft reserve uses.  r193-r199 sized it `win + n_ubatch`, so once the first sequence filled the window a second sequence's batch had no contiguous run to be placed in (`find_slot`'s SWA reclaim frees a cell by its OWNER's position) and every request on that slot answered HTTP 500 `decode() failed: failed to process speculative batch`.  Two arms on one binary (`win` = a small forced window, `win0` = off) drive 2 slots through 6 requests: slot 0 fills its window, slot 1's own batch is the #264 failure, then both slots are re-prefilled with the other slot's prompt (both rings wrap) and finally served from cache.  **Fails** unless: every request answers on both slots, the windowed arm's draft cache really is `(win + UB) x NPAR` cells (a declined window would make the comparison vacuous, and the r193-r199 shape is exactly half), the windowed arm's text equals the no-window arm byte for byte on every step, and neither arm aborts or reports `failed to find a memory slot`.  Acceptance per slot is printed as INFO (the window is an approximation, so a difference there is expected and a *text* difference is not).  `WIN=auto CTX=262144 PROMPT=<a >32768-token prompt> PROMPT2=<another>` reproduces the reporter's own shape.  Model/flags are environment (`MODEL`, `PROMPT`, `PROMPT2`, `WIN`, `CTX`, `NPAR`, `NGEN`, `SM`, `NCMOE`, `NGPU`, `UB`, `PORT`, `EXTRA_ARGS`, `KEEPOUT`); ~2 min on one GPU. | any change to the draft window's sizing, `llama_spec_draft_kv_cells()`, `create_memory`'s MTP branch or the derived draft reserve; every release that touches block 15 |
| `gate-spec-reuse-window.sh` | The **drafter KV reuse** gate (r218, issue #272, `LLAMA_DFLASH_INGEST_TAIL` / `LLAMA_MTP_INGEST_TAIL`).  A draft's own KV cache must stay contiguous with the rows a `process()` call ingests (the batch check wants the first ingested position to be the cache's `seq_pos_max + 1`).  A prompt is routinely only PARTIALLY reused - the slot keeps a prefix from an earlier task - so a turn that adds more than the tail's length leaves the draft's rows ending below its first ingested row: a strict (non-M-RoPE) draft has its injection batch REJECTED (`inconsistent sequence positions` -> HTTP 500 `decode() failed: failed to process speculative batch`) and an M-RoPE draft silently ingests a batch that attends to nothing.  The gate replays three turns of one prompt, each adding a full 5246-token prose chunk, in FOUR arms: the draft as shipped and a derived **non-M-RoPE** copy of it (zeroing `dflash.rope.dimension_sections` - the reporter's shape, and measurably the *same* model: identical acceptance, only the batch-check rule changes), each with the tail on and with `LLAMA_DFLASH_INGEST_TAIL=0`.  **Fails** unless every request answers in every arm, no log carries `inconsistent sequence positions` / `failed to process speculative batch` / an abort, the tail arms really armed the window, each turn really added more than the window (or the reuse jump was never created), and the tail arm's text equals the no-tail arm's byte for byte. Model/binary/flags are environment (`LLAMA_SERVER`, `MODEL`, `DRAFT`, `BASE`, `CHUNK`, `CTX`, `NPAR`, `NGEN`, `PORT`, `DERIVED`, `EXTRA_ARGS`, `KEEPOUT`); ~8 min on one GPU (4 server starts). | any change to a drafter's ingest decisions (the DFlash/MTP tail, the draft checkpoint restore, `common_speculative_impl_draft_{dflash,mtp}::process()`, `spec_draft_align_cache()`); every release that touches block 02 or 12 |
| `gate-host-pool.sh` | The **host-expert pool** gate (r219, issue #274).  A pool fill has two possible sources: the read-only model mapping (a plain `memcpy` out of the page cache, always present because the pool's master IS that mapping) and the pool's **disk tier** (`MOE_HOST_POOL_DIO=1`, `pread`/`O_DIRECT`), which is a POSIX feature and a compile-time stub returning -1 on Windows.  Treating the disk tier as required is what broke issue #274: on Windows every pool fill failed, every pool marked itself failed (so `table_pool_locked()` returned null and the pool "never appeared"), the bounce fallback asked for the same missing tier, and `access_locked()` recorded the slot as RESIDENT anyway -- the arena served stale bytes (20 t/s prefill, one token, then EOS).  Four arms on one pool-backed host-expert config, same-seed greedy: shipped / `MOE_HOST_POOL_DIO=1` / `MOE_HOST_POOL_DIO_FAULT=1` (a platform with NO disk tier: the Windows shape) / `MOE_HOST_POOL_FILL_FAULT=1` (no source can be resolved at all).  **Fails** unless all four texts are byte-identical, the three healthy arms build a real pool (slots > 0, MiB pinned > 0) with no fill failure, `nodisk` is not vacuous (the refusal is logged), and the forced-failure arm stays CORRECT with `FAILED fills: N` in the census and `the slot is NOT resident` per table.  Model/gpu/flags are environment (`LLAMA_CLI`, `MODEL`, `GPU`, `CTX`, `UB`, `NCMOE`, `LIMIT_FRAC`, `PROMPT`, `PROMPT_FILE`, `NGEN`, `EXTRA_ARGS`, `KEEPOUT`); ~2 min on one GPU (4 `llama-cli` starts, pool prewarm dominates). | any change to the pool's fill/staging, `expert_host_src()`, `access_locked()`'s admission, the `-lme`/`--host-experts pool` placement or the loader's host-expert source registration; every release |
| `gate-kv-window-split.sh` | The **windowed KV across a `-sm tensor` split** gate (r204, `TODO` #124, `LLAMA_KV_RESIDENT_CELLS`).  The window is one VMM region **per child device** of the Meta wrapper (every child commits the same `W` cells of its own slice), the grow fans out to every child, and `--fit` sizes it against the split's per-device budget. | `check-windows-portability.sh` | Fails if a file the delivery **adds** calls a POSIX-only function (`open`/`close`/`pread`/`fsync`/`access`/`sysconf`/`getpid`/`posix_memalign`/`mmap`/...) outside a Windows-excluding preprocessor region. | `moe-trace-replay.py` | The **offline MoE expert-cache policy replayer** (r110, TODO #61 P1): reads an `MOE_EXPERT_TRACE` file and scores the shipped F-LRU, an oracle static top-f, a per-layer capacity quota and pass-start pre-admission against it, reporting `h`, the missing/cold split, expert MiB/token, resident bytes and covered mass, plus the global-top-f static bound. ## Notes

* **`release.json` is the only source of truth** for the fork point, tip/tree, block count and hashes.
  `apply-all.sh`, `fork-refresh.sh`, `validate-set.sh`, `make-patches.sh`, `make-release.sh`, `build-containers.sh`,
  `container-watch.sh` and CI all read it; if a script disagrees with the manifest, the manifest wins.
* **Order matters on a release:** `make-patches.sh` → `fork-refresh.sh` (re-cut; it prints the tip to
  record) → `make-release.sh --tip <printed>` (+ `--tree`, which `fork-refresh.sh` also prints) →
  `validate-set.sh` → commit → tag.  A tag cut before `make-patches.sh`/`make-release.sh` ships a
  manifest that does not match `patches/`, and a tag cut before the fork refresh ships a stale branch.
  **`--tip` is always the fork branch tip that `fork-refresh.sh`/`apply-all.sh` printed, never the tip of
  the working chain in `~/llama.cpp`** (same tree, different commit id); the rule is in `AGENTS.md`.
* **The gates are not interchangeable.**  Coherence (same-seed text) is blind to a uniform prefill shift;
  the prefill-logit gate is blind to decode drift; MTP is blind to both.  `MANIFESTS.md` lists which gate a
  given block needs.
* **Run GPU gates alone.**  Two concurrent GPU jobs change the arena/band layout and invent failures.
* `--help` on any script prints its header comment (the option list) without running anything.
