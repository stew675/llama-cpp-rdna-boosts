# The low band (2..5 columns): measured, and it cannot be won — plus the per-type crossover (r312, `TODO` #329 retired)

**Verdict: `TODO` #329 is REFUTED, not implemented.**  The item's premise was that the family's low end loses
"because the kernel streams the whole weight row whatever the column count", so that a *narrower tile* (or a
dot-product form) "would let the floor go to 2 and make the family default-on".  Measured, the reference is
not a kernel at 2..4 columns but the **DRAM roof**: the K-split `mmvq` kernel runs at 92-98 % of this box's
memory bandwidth there, so the whole headroom in the low band is 0-8 % *before* any tile-vs-tile comparison,
and the family's fixed 16-column tile lands 2-8 % behind it.  Nothing narrower can help, because nothing
narrower reads fewer bytes.

What the measurement *did* buy is the thing the item was really about: the crossover is **type-shaped**, so
`auto` is now a per-type floor instead of the blanket 7 — worth **+2.9 % at 6 columns** end to end, and it
removes the 7-column loss the blanket floor still paid on Q6_K.

Box: 1 × R9700 (gfx1201, 644 GB/s spec) and the `0,2` x8 pair, ROCm 10.1.0, `~/bin/build-llama-rocm`.
Models: `Qwen3.8-27B-UD-Q4_K_M` (a mixed K-quant/IQ4_XS model), `Qwen3.8-27B-Q8_0` + its DFlash2 `Q4_K_M`
drafter, `Qwen3.5-4B-Q8_0`.

## 1. The isolated op, DRAM-cold: this is where the roof shows

`tests/test-backend-ops perf -o MUL_MAT -p "m=88064,n=[1-8],"`, one dense `MUL_MAT` at `m=88064, k=5120`
(253 MB per Q4_K matrix — larger than the 64 MB L2, so every timed iteration streams from DRAM).  A
`m=11008` matrix (32 MB) is L2-resident and reads 2-3x optimistic — that is how the low band can look like a
win — so **use `m >= 65536` for this class of measurement**.

**Reading it honestly.**  `*` = inside the cross-process drift.  One `avg_time_us` repeats to ~0.1 % *within* a
run, but each arm is a fresh process and the two arms differ in power draw (the tile form issues 2-4x the
MMA), so sustained clocks make the same cell differ by up to ~1.5 % between an "off" run and a "tile" run
(measured: `Q5_K` width 4 reads 521.0/522.1 in two separate off runs and 529.9 in the auto run, where it is
the SAME kernel).  Every decision below therefore uses an effect **at least twice that** — and the low band's
verdict does not depend on any of them: at 2..4 columns *no type* gains more than 2 %, whatever the drift.

That is the whole argument: **the K-split kernel is at the memory wall for the first four columns of every
type**, so the low band is competing with physics.  The family's own bandwidth is ~547-604 GB/s there, which
is exactly the 2-8 % the table shows.

Why the tile form cannot close it: a 16x16x16 `iu8` WMMA computes 16 columns whether or not they carry data,
so at 2 columns the family does 8x the arithmetic it needs for the same weight traffic; its cost is *nearly
flat* in the column count (410.6 -> 454.4 µs for Q4_K from 1 to 8), which is the feature at 7-8 columns and a
tax below 5.  A narrower tile does not exist (the instruction shape is fixed) and a dot-product form would
have to beat a kernel that is already at the wall.

## 2. Adjacent ideas, measured and rejected

**(a) The min term's MMA is half of the Q4_K/Q5_K tile cost, and removing it is not worth the machinery.**
Q4_K and Q5_K spend 2 of their 4 MMA per 32-element sub-block on the `Σxq` "ones" matmul.  Zeroing it (wrong
output — a timing bound only) gives Q4_K **+2.2 % at 2 … +5.0 % at 8**, Q5_K **+0.6..0.8 %**, and **0.0 %**
for Q6_K / IQ4_XS / Q8_0 (which have no min term).  It does not move the crossover (Q4_K would still read
-1.1 % at 2 and -0.7 % at 3), and the exact replacement — a per-(column, K-block) `Σ xq` table precomputed once
per op and shared by all 16 rows — is a new precompute kernel plus a scratch buffer plus a new exactness
argument.  Rejected: <= +5 % on one type's already-winning widths.

**(b) The wave-count rule is not the low-band problem either.**  `nsb = k/256`; the launcher picks 10/8/4/2/1
waves and requires an exact divisor, so `k = 3840` (Gemma 4's `n_embd`, `nsb = 15`) falls through to ONE
32-thread wave.  Letting the largest W with the shortest critical path win instead (`nsb = 15` -> 10 waves) is
**±1-2 % with mixed signs**: Q4_K at 8 columns 547.3 -> 541.6 GB/s (**worse**: 320-thread blocks pay more LDS
reduction and registers) while Q8_0 goes 583.4 -> 597.7 (better) and Q4_K at 2 columns 576.7 -> 610.5.  The
exact-divisor rule stays; the comment in `launch()` records the numbers so it is not "simplified" again.

## 3. What shipped: `auto` is the measured per-type floor

| type | measured crossover | `auto` floor |
|---|---|---|
| Q4_K | -1.7 % at 4 (noise), **+6.7 % at 5** | **5** |
| Q5_K | +1.8 % at 4 (noise), **+12.9 % at 5** | **5** |
| Q6_K | **-7.5 % at 2 … -8.2 % at 6**, -1.1 % at 7 (noise), **+5.4 % at 8** | **8** |
| IQ4_XS | -2.5 % at 2, -1.0 % at 7 (noise), +0.3 % at 8 (noise — neutral, never a win) | **8** |
| Q8_0 | parity to 7, **+4.3 % at 8** | **8** |

`--wmma-verify auto` (and `GGML_CUDA_WMMA_MMVQ=auto`) resolves that table in ggml; an explicit `N` stays the
uniform floor for every type (the calibration/A-B arm, and `=7` reproduces r311 exactly).  The default is
still **off**.

than trying to squeeze width 4.)

## 4. Purity / what the release must prove

* **OFF arm unchanged**: 27B Q8_0 + DFlash2 `--spec-draft-n-max 7`, 2 × R9700 `-sm tensor`, 96 greedy tokens,
  seed 42 -> `56612340f420` on **both** the r311 and r312 builds.
* **The family's numerics unchanged**: an explicit `GGML_CUDA_WMMA_MMVQ=7` on the same arm -> `b7d28482ca5f` on
  **both** builds (r312 only changes *which* types/widths select the family, never its arithmetic).
* **The family is not verify-only**: a plain `llama-cli` prefill on 4B Q8_0 (`-b 2048 -ub 512`, 12 tokens)
  dispatches it 639 times out of 2419 matvec ops at floor 2 (all before the first decode step), and the 40-token
  greedy text moves (`ed4ee91ec5b6` off vs `1b72606b6cf9` on).  So the option's warning is about the greedy
  contract in general, and a gate can never assume "the ON arm only runs at verify".
* `GGML_CUDA_WMMA_MMVQ=auto` is read by its first letter (`atoi("auto")` would silently mean `0` = off).

## 5. What is still true, and what would re-open this

The family is **width-split by design** (1 column is decode and keeps the K-split kernel), which is
`GREEDY-PURITY.md` invariant 1 broken by construction — that, and not the low band, is what keeps it opt-in.
Re-open only with a *different* invariant: a kernel that wins at **1** column as well (so decode and verify take
the same family), or a mechanism that beats the DRAM roof (fewer bytes per weight, i.e. a smaller weight
format), neither of which this campaign found.  Do not re-measure the low band expecting a tile-shaped win: it
is 0-8 % of headroom against a kernel that is already 92-98 % of the wall.
