## `40c0b9c38` — "drop the dense mask only where the qsa3 kernel will consume the op"

**Reference bug.**  `LLAMA_QSA_NO_DENSE_MASK` let the QSA op run with `mask=nullptr` and rely on the
selected-cell indices (`src[5]`) to carry visibility.  That is sound only for the qsa3 kernel, which
reads those indices and honours the `-1` sentinel.  No other flash-attention kernel looks at `src[5]`,
so a maskless op reaching one of them attended to the **entire padded KV cache** (future positions,
foreign cells, never-written slots).  Because maskless was decided from the graph input alone and
qsa3 additionally needs both packed layouts and `>= 128` queries — true in prefill, false in decode —
**every decode step** ran dense and unmasked over stale cells, which is what made long greedy
generations non-deterministic (10/10 → 1/10 after the fix).  The fix decides maskless at the use site
(`qsa3 && ...`) and adds a dispatcher assert so a future gate change fails loudly.

**Our tree: N/A — we have no maskless path, and every consumer of a maskless QSA op honours visibility.**

* There is **no `maskless` / `NO_DENSE_MASK` flag at all** (`rg maskless|NO_DENSE_MASK
  src/models/qwen4exp.cpp` → nothing).  The reference's `tail_idxs`/`compact`/`maskless` design is not
  ours; ours is the **derived-visibility** design (`cell_vis`/`q_vis`, `blk_idx`/`blk_tail`,
  `qwen4exp_derived_vis_enabled()`).
* In `build_attn_qsa`, the derived path sets `kq_mask = qsa_derive_vis ? nullptr : inp->get_kq_mask()`
  (**src/models/qwen4exp.cpp:1692**), i.e. the mask is dropped only when `cell_vis`/`q_vis` are
  present, and the op is `ggml_flash_attn_qsa` — which **always** dispatches to a QSA kernel
  (`fattn-qsa.cu::ggml_cuda_flash_attn_qsa`), never to the generic FA path.
* **Both** QSA kernels read the derived keys:
  * VEC/tile: `fattn-qsa.cu:122-131` — `qsa_cell_mask` uses `cell_vis[c] <= q_vis` when present,
    else `maskh[c]`; a derived op has `cell_vis != nullptr`.
  * packed WMMA: `fattn-qsa3.cu:371-372, 462` — same predicate (`cv >= 0 && cv <= own_q_vis`).
* The qsa3 kernel **refuses** a maskless op without derived vis: `fattn-qsa3.cu:620-621` returns
  `false` for `!mask && (!src[5] || !src[6])`.  So the `n_query < 128` decode band that bails out of
  qsa3 falls to the VEC kernel, which honours `cell_vis` too — the reference's exact failure mode
  (bail to a kernel that ignores the keys) cannot happen.
* The one other "derived visibility, no mask tensor" path — the V3 derived kq mask on
  `GGML_OP_FLASH_ATTN_EXT` (`src[5]` = derived marker, `src[3]` = null) — is guarded in
  `ggml_cuda_flash_attn_ext_supported` (**fattn.cu:853**): it returns `false` unless the chosen kernel
  is `MMA_F16` or `TILE`, so a derived op can never reach a kernel without the derived arm.  The graph
  then falls back to the packed mask (clean degradation) rather than aborting or attending unmasked.

The reference added a hard `GGML_ASSERT((dst->src[3] || !dst->src[5]))` in its dispatcher.  Our
equivalent is the **support-probe** (`..._supported` returns false), which is strictly gentler: it
routes around the bad kernel instead of aborting the process.  No change needed.

## `14fff4f97` — "keep the −1 selection sentinels out of the masked attention path"

**Reference bug.**  `select_complete_blocks` writes `-1` into the selected-cell list for the cells of
an invisible block and for empty tail slots.  Only the maskless selected-key kernel understands `-1`.
The tails were allocated whenever block selection applied, so with a **non-scalar** visibility
(2-D image positions in the cache, or several sequences) the maskless kernel was not taken and the
selection went to the **masked** path, whose `set_rows` wrote row `-1` — an illegal memory access
(`k_set_rows` on gfx1151, reproduced with an image after 12k tokens).  The fix allocates the tails and
performs the complete-block join **only when the visibility is scalar**; otherwise it uses the
block-expanded top-k with the per-block bias, as before.

**Our tree: N/A — our selection list is a radix top-k of real cell indices; the `-1`/`INT32_MAX`
sentinels are kernel *inputs*, never output.**

* The selection list is `top_k`, produced solely by `ggml_indexer_top_k`.  Its output is written as
  `row_dst[...] = col` / `= c` where `col`/`c` walk `[0, n_kv)` (**indexer-topk.cu:402,406,519,523**);
  the `-INF` bin is filled with a **real cell index**, so every one of the `k` slots is a valid index
  — there is no "invisible block gets −1" entry to begin with.
* The `-1` (incomplete block) and `INT32_MAX` (spare block) sentinels live **only** in the kernel
  inputs `blk_idx`/`blk_tail` (**indexer-topk.cu:53**, filled in
  `llama-memory-hybrid-idx.cpp:758`), where `indexer_topk_block_key`/`indexer_topk_value` consume them
  as `-INFINITY` / `1e9` scores.  They are never copied to the output.
* `cell_blk` — the other index-like input the top-k uses to address `score[...]` — is mapped to a
  valid block id: `cur_cell_blk[j] = blk_of[j] < 0 ? dead_bid : blk_of[j]`
  (**llama-memory-hybrid-idx.cpp:750**), and `dead_bid` is in `[0, n_blocks)` even when no spare block
  exists.
* Therefore the `ggml_set_rows(kq_mask_all, zeros, top_k_3d)` in our dense path
  (**src/models/qwen4exp.cpp:1714**) indexes rows in `[0, n_kv)` — no row `-1`.  And even a cell that
  *should* have stayed hidden is re-masked by the following `ggml_add(kq_mask_top_k, kq_mask)`
  (line 1724), so a wrongly-unmasked cell could not change attention either.
* Reachability note: that `set_rows` is only **consumed** by the dense fallback (`build_attn_mha`,
  line 1757).  In the default gfx1151 sparse path (`qsa_sparse == true`) the QSA op receives
  `kq_mask`, not `kq_mask_top_k`, so the `set_rows` is dead there — the concern is confined to a path
  that cannot produce sentinels anyway.

### A defensive note for a future change

The reference's `40c0b9c38` assert is cheap insurance.  Our VEC QSA kernel dereferences `maskh[cell_g]`
when `cell_vis == nullptr` (**fattn-qsa.cu:135**), so an op with **both** mask and derived keys null
would fault; today the graph cannot build that (mask is dropped only when the keys exist), but nothing
in the kernel or the support probe asserts it.  If a future change makes `maskless`-style decisions
differently, add the reference's invariant at the use site (`GGML_ASSERT(!maskless || qsa3)`), or
enforce `(mask != nullptr) || (cell_vis != nullptr)` in `ggml_cuda_flash_attn_qsa`.
