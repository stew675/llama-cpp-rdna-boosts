## §8#1 `0029` — **no-op on gfx1151** (confirmed)

The fix matters only when a *non-empty* CPU input split graph exists.  With `0025`, the gfx1151 APU
keeps `token_embd`/`per_layer_token_embd` host-resident zero-copy and runs the `GET_ROWS` on ROCm0, so
that split does not exist.  qwen4exp IQ4_NL MTP `n8`, prose, `-n 3000`, `-c 16384 -b/-ub 2048`,
CPU sampled by `tools/mon.py`:

| arm | gen t/s | acceptance | CPU steady mean | text |
|---|---:|---:|---:|---|
| default (`0029` on) | 56.5 | 0.66582 | 1.36 | `a6f3adda3f11` |
| `GGML_CPU_DISABLE_TINY_GRAPH_SINGLE_THREAD=1` | 55.7 | 0.66582 | 1.36 | `a6f3adda3f11` |

**No-op, byte-identical.**  Verdict: keep the default; the kill-switch changes nothing here.

## §8#2 `0030` — **no-op on gfx1151** (not a loss)

`LLAMA_DEVICE_INPUT=1` (move the input layer to the output/Meta device) on the same run:

| arm | gen t/s | acceptance | CPU steady mean | text |
|---|---:|---:|---:|---|
| default (host input) | 56.5 | 0.66582 | 1.36 | `a6f3adda3f11` |
| `LLAMA_DEVICE_INPUT=1` | 56.4 | 0.66582 | 1.37 | `a6f3adda3f11` |

On the APU the input is already host-resident zero-copy, and the device placement is throughput-neutral
(gfx1201 saw −2.6 %).  **Keep the default (host input) and keep `0030` opt-in.**

## §8#5 `0001` / `0008` isolated A/Bs — **both defaults hold**

qwen4exp IQ4_NL `llama-bench -p 8192,32768 -n 0 -b 2048 -ub 2048 -r 3`, interleaved 2 reps (S_PP t/s):

| arm | pp8192 | pp32768 | Δ vs default |
|---|---:|---:|---:|
| default | 1259.6 | 1216.4 | — |
| `LLAMA_FUSED_DSV4_HC_POST=1` (the `0001` op alternative) | 1244.8 | 1195.9 | **−1.2 % / −1.7 %** |
| `GGML_CUDA_MMB_TALL_MIN_M=0` (`0008` off) | 1240.1 | 1203.2 | **−1.6 % / −1.1 %** |

The default `hc_combine_norm` graph-optimizer fusion and the default `TALL_MIN_M=16` are both ahead.
`0001` and `0008` stand on gfx1151 (the gfx1201 deltas were −5 % and −0.6 %; the gfx1151 margins are
smaller but consistent).

## §8#7 `0011` HC BF16 streams — **`res16` is a real gfx1151 win; stays default-OFF (lossy)**

Same bench, same interleave:

| arm | pp8192 | pp32768 | Δ vs default |
|---|---:|---:|---:|
| default | 1259.6 | 1216.4 | — |
| `LLAMA_HC_BLK16=1` | 1253.6 | 1217.4 | −0.5 % / +0.1 % (**inert**) |
| `LLAMA_HC_RES16=1` | 1290.8 | 1240.9 | **+2.5 % / +2.0 %** |
| `LLAMA_HC_BLK16=1 LLAMA_HC_RES16=1` | 1294.4 | 1244.0 | **+2.8 % / +2.3 %** |

The gfx1201 shape reproduces on the APU: the win is **all `res16`** (the in-place BF16 residual
stream); `blk16` is inert (its producer check fails on qwen4exp).  The gfx1151 margin (+2.0–2.5 %) is a
little larger than gfx1201 `-sm tensor` (+1.3 %).  **Decision unchanged: park** — it is lossy prefill
and the maintainer keeps it default-OFF; the inert `blk16` half remains a follow-up if it is ever
revisited.

## §8#6 `0005` M-RoPE image + MTP — **harness built; clean on both builds; not reproduced**

Built a gfx1151 adaptation of [`tools/mrope-image-mtp.sh`](tools/mrope-image-mtp.sh) (single GPU, no
`-sm tensor`, `/opt/rocm-7.14-gfx1151`): `llama-server` + qwen4exp **IQ4_XS** + `mmproj-BF16.gguf` +
the shared Q8_0 MTP head (`-md`), `--spec-type draft-mtp --spec-draft-n-max 3`,
`-ctk/-ctv q8_0 -c 28672 -b 4096 -ub 2048 --image-min-tokens 4096 --image-max-tokens 4096`, then a
`/v1/chat/completions` with ~12k tokens of text first and a 512×512 image second (~19903 prompt
tokens, 1000 generated).  Two builds:

| build | prompt | generated | MTP | result |
|---|---|---|---|---|
| **current** (`0005`) | 19903 tok | 1000 | 678/962 accepted (0.70478) | **clean** |
| **pre-fix** (`0005` disabled: `qsa_n_kv_window()` → `get_n_kv()`) | 19903 tok | 1000 | 678/962 accepted (0.70478) | **clean** |

No abort, assert, `X < Y`, block-fill overrun or non-finite in either arm; the outputs are identical.
**The gfx1151 trigger does not reproduce** either — it requires the **pre-r13** state where the shared
MTP head reuses the target's KV.  r13 block 00 (`is_mem_shared` gated on `gemma4-assistant`) gives the
shared head its **own** KV, so the draft context no longer inherits the target's image/position
divergence.  This is exactly the gfx1201 OP-4(d) conclusion.  **Verdict:** `0005` stays as a faithful
port of the reference `b0f31f587` and a correctness guard; the gate is **"runs clean"**, not a
FAIL→PASS.  The harness and the request builder are reusable if a non-shared qwen4exp head lands.
