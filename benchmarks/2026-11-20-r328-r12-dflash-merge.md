# DFlash on the r328 re-base (R12): the delivery's feature set vs upstream's behaviour — record

Measurement behind **D17** in `archive/work/upstream-rebase-261120/DECISIONS.md` and the R12 log in
`archive/work/upstream-rebase-261120/RUNGS.md` (§R12.4).  It answers the maintainer's instruction of 2026-11-21 —
*"the best way to make a decision on which way to go with the dflash choice is to measure which is more
performant … I am reticent to drop its work for upstream's"* — by measuring the **feature set** the delivery
built on top of the DFlash speculator, now that R12 merged that class onto upstream `#32016`'s
`dflash_options`/`init(opt)` seam.

Nothing here is part of the delivery's gates: it is the evidence for a decision taken during the re-base.

## 0. What was NOT a question

The three graph builders are not a performance fork.  `build_dspark_markov_head` and `build_lilicorr_scores`
are byte-identical between upstream's new per-campaign files and the delivery's `src/models/dflash.cpp`
(7,037 B and 11,151 B), `build_dflash2_conv` differs only structurally (class member vs static function), and
`build_dflash2_selector` differs by exactly one block: the delivery's **all-gather of the vocab-split logits**.
That block is a **correctness** fix, and §5 shows it: the pristine base aborts the same arm.

## 1. Cell

gfx1201 (R9700), ROCm 10.1.0, r328 ladder build (`~/llama.cpp/build-rocm`, tree
`f0f9db34b1c3ae8a93f834e5c2fad472113a1af9`), one GPU workload at a time, `HIP_VISIBLE_DEVICES` pinned.

| target | draft head | layout |
|---|---|---|
| `Qwen3.8-27B-UD-Q4_K_XL` | `Qwen3.8-27B-DFlash2-Q4_K_M` | 1 GPU, `-sm layer` |
| `Qwen3.6-35B-A3B-Q8_0` | `Qwen3.6-35B-A3B-DFlash2-Q8_0` | `HIP_VISIBLE_DEVICES=0,2`, `-sm tensor -mg 0` |
| `Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S` | `Qwen3.8-Flash-Next-DFlash2-Q8_0` | `HIP_VISIBLE_DEVICES=0,1,2`, `-sm tensor -mg 0` |

Common args: `-ngl 99 -fa on -ctk q8_0 -ctv q8_0 -ub 2048 --spec-type draft-dflash
--spec-draft-n-max 7 -n 2000 --seed 42 --temp 0 --no-display-prompt --single-turn -lv 4`, `-c 16384`
(6K cells) or `-c 32768` (26K cells).  The head's block size is 8, so 7 is the ceiling.

Prompt: `prompts/prose-rdna-boosts.txt` (5,246 tokens, sha256 `fabdec65…3667727`) for **6K**; the same file
repeated five times (26,230 tokens) for **26K** — a scratch file, so the *content* is the sha-pinned prompt
repeated, and every arm of a size uses the same file.

`-lv 4` puts every census on **stderr** and leaves the generated text on **stdout**, so one run per cell gives
both the text hash and the acceptance statistics (`SPC_TRC`'s `statistics … #acc rate/pos`).  Prefill rate is
the run's own `[ Prompt: … | Generation: … ]` footer — the ingest tail's win is a prefill win, DFlash2's own
win is a decode win, and they are reported separately.

## 5. `U-st`: the `-sm tensor` correctness arm — upstream aborts, the re-based tree runs

The same 35B-A3B + DFlash2-Q8_0 command on the pristine base (`build-base-novmm`, `919794500`,
`GGML_HIP_NO_VMM=ON`):

```
ggml/src/ggml-backend-meta.cpp:573: GGML_ASSERT(src_ss[0].axis != GGML_BACKEND_SPLIT_AXIS_0) failed
```

— upstream's async-split-state `handle_per_row` refusing a per-row op over a row that straddles a device
split, which is the DFlash selector shape.  The **plain control** (same model, same 2-GPU tensor layout, no
draft model) runs on the same base (`150 chars sha=4ac3a523160f`), so this is DFlash-on-a-tensor-split and not
the base's MoE path.  The re-based tree runs every arm in §3 clean.

## 6. Reading, per knob (never per file)

* **Ingest tail** (`LLAMA_DFLASH_INGEST_TAIL`, default on): +9.1 % pp at 6K and **+29.8 %** at 26K on the
  35B/2-GPU arm; +2.3 % / +11.7 % on Flash-Next/3-GPU; **~neutral on the 27B because that cell is a 1-GPU
  `-sm layer` split** (D 1252.4 vs D-it 1248.9 at 6K, 1201.2 vs 1192.7 at 26K).  The mechanism is the draft's
  encode plus the per-batch target wait overlapping the target's prefill, so a single device has nothing to
  overlap — this reproduces the delivery's own r130 record (`-sm layer` neutral, 3-GPU tensor +8-12 %).  A
  future re-check must use a tensor split or it will wrongly conclude the feature is dead.
* **F1 device-resident features** (`LLAMA_DFLASH_DEV`, default on): the 27B/1-GPU cell at 6K is 1252.4 (D) vs
  1221.6 (D-f1) ≈ **+2.5 %**, and 1248.9 (D-it, tail off but F1 on) vs 1163.9 (U, both off) ≈ **+7.3 %** — i.e.
  on this cell F1 is the 6K term, not the tail.  Decode flat.
* **Decode is flat** on every arm (±0.5 %, single-run noise), which is the expected direction: these are
  prefill features.  So no arm here can be read as a decode regression, and none is.
* **F1 is inert on both MoE heads**: their draft contexts fail `llama_supports_embd_row()` and log
  `DFlash target features via host copies`, so the knob is a dense-model win today (`TODO` candidate: wire the
  device-row path for the MoE draft heads, or record the limitation).

## 7. Decision (D17)

Keep **upstream's file layout, class split and `init(opt)` seam**, and the **delivery's whole feature set on
top** — ingest tail on (`LLAMA_DFLASH_INGEST_TAIL=0` off), F1 on (`LLAMA_DFLASH_DEV=0` off), the ported
all-gather in `build_dflash2_selector`, and DFlash2's selector/probabilistic paths plus DSpark's anchor layout
as upstream now has them.  Nothing was deleted from the delivery's work; what went away is the build's second,
pre-split copy of a class upstream had already distributed, which is what blocked the paused R12.
