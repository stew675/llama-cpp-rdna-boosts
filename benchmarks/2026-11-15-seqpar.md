# Sequence parallelism for the qwen4exp hyper-connections (block 12, r291) — record

Contributor PR #315 (@briansp2020, 5 patches against r289) folded into **block 12** as the r291 amendment,
with the 3-card extension made here.  This file is the measurement record behind `INVARIANTS.md` r291,
`GREEDY-PURITY.md` §92, `ENVIRONMENT.md` §21 and the block-12 note in `patches/README.md`.

**What it is.**  Under `-sm tensor` the hyper-connection chain (mixers, combine, gated norms, the shared
expert and the GEMMs over them) used to be mirrored: every device ran it for every token of a ubatch.  With
`LLAMA_SEQPAR` on (default) a prefill ubatch of at least `LLAMA_SEQPAR_MIN` (512) tokens on a 2+-device
`-sm tensor` layout keeps the residual streams token-split from layer 0 to the last layer: each block
gathers its `hc_mixed` input for the feature-split parts, the shared expert runs on local tokens, and the
attention and MoE partial sums are reduce-scattered by token.  PLE layers and the last layer run on the
gathered streams.  Decode and verify graphs are 1..n_draft+1 tokens, below the threshold, and never split.

**Cell.**  2 x R9700 (gfx1201), PCIe 5.0 x8, ROCm 10.1.0, `ROCBLAS_USE_HIPBLASLT=0` for every text/hash/PPL
arm (`INVARIANTS.md` §44), `MOE_EXPERT_HEATMAP=load` on every arm (`GREEDY-PURITY.md` §89).  Model:
`/llm/models/Qwen3.8/Flash-Next/GSQ-IQ3_XXS/Qwen3.8-Flash-Next-GSQ-RCO-IQ3_XXS-00001-of-00002.gguf`,
`-sm tensor -ncmoe 47 -ot per_layer_token_embd.*=CPU`, `-ub 4096` for the throughput arms (T = 1024 for the
text/census arms).  Prompt: `prompts/prose-rdna-boosts.txt` (sha256
`fabdec65f5859e5508cc863a6e5f976706d5a770bb53eb1b406dc5aee3667727`, 16074 B).  The prefixes below are the
first 12 hex of `scripts/extract-generated.py`'s sha256.

## 4. Memory

The allocator breakdown is identical on and off (`-c 4096 -ub 4096`: Meta device 3159 / context 116 /
compute 2560 MiB).  The feature's own device memory is the copy-engine scratch, which is *raw* device memory
outside the ggml allocators, so it only appears in the census: `3 x 5.00 MiB per device` at `-ub 1024` and
`3 x 20.00 MiB per device` at `-ub 4096` on the default chain; on the copy-engine chain the scratch already
exists for the all-reduce and the gather reuses it without growing it.

## 5. The T < 128 band is clamped off (`TODO` #330 is the cache fix)

With `LLAMA_SEQPAR_MIN=2` (forced) the Meta split-state recursion can overflow the stack: reproduced at
T = **48, 64, 80, 112** (`llama-bench -p 4096` / `-p 8192`), clean at 32, 96, 128, 144, 160, 192, 200, 224,
240, 256 (`-p 24576`), 320, 512, 1024, 2048, 4096, 31500.  seqpar OFF at the same T is clean, and
`LLAMA_SEQPAR_MIN=128` makes every one of those arms clean too.  Separately, with `LLAMA_SEQPAR_MIN` <= 2 a
**2-token graph** (the common warmup) trips the token-scatter split-state assertion deterministically
(`ggml-backend-meta.cpp:1953`, `src_ss[0].axis == MIRRORED`), so the band has two distinct failure modes.

Because both are unreachable at 128 and above, the value is **clamped to 128 with one WARN** rather than only
documented: `LLAMA_SEQPAR_MIN=2` at `-ub 32` now exits 0, prints the clamp warning and reports
`not engaged: ubatch of 32 tokens (below LLAMA_SEQPAR_MIN = 128 ...)`, while `MIN=128 -ub 128` engages and runs
clean.  The shipped default (512) is above the clamp and unchanged, and `scripts/gate-seqpar.sh` arm 6 asserts
the clamp.
gdb: unbounded `calculate_split_state` <-> `ggml_backend_meta_get_split_state` (block 09's cache, see the
`TODO` entry for the mechanism and why it is not fixed here).
