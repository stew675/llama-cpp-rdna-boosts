# The SSM gate/beta fusions computed softplus in the wrong rounding (#265, and the #263 acceptance class)

**r201, blocks 08 + 10.**  Boxes: `soar` (gfx1201, 1 x R9700 used for every arm here; 3 cards present),
`fingon` (gfx1100, 1 x RX 7900 XTX -- the #263 reporter's arch).  Both builds are the same tree; every
text comparison ran with `ROCBLAS_USE_HIPBLASLT=0`.

## The defect

`ssm_gate_beta_fused_q8_0` (`mmvq.cu`, `GGML_CUDA_FUSE_GATE_BETA_VERIFY`) and the BF16 sibling's epilogue in
`mmvf.cu` (`GGML_CUDA_FUSE_GATE_BETA_BF16`) computed

    gate = softplus(alpha*x + dt) * a    with    softplus(x) = logf(1.0f + expf(x))

while `unary.cu`'s `op_softplus`, the ADD -> SOFTPLUS -> MUL chain they replace, computes
`log1pf(expf(x))`.  Those are not the same float.  Both fusions are contractually *bit-identical* to the chain
(`GREEDY-PURITY.md` §19/§24/§25), and were not.

## Where it was visible, and where it was not

| arm | result |
|---|---|
| `gate-prefill-logits.sh --ub 1 --ab "GGML_CUDA_FUSE_GATE_BETA_VERIFY=0"`, gfx1201 | **0.000000 / 100.000 %** -- *vacuous*: at one token the SSM pre-scan fusion takes those nodes on qwen3.5/3.6/3.8, so the fusion under test never ran |
| `... --ub 4 --ab "..."`, gfx1201 (27B Q8_0) | **0.000562 KLD / 99.000 %** (fail: not the chain) |
| `... --ub 4 --ab "..."`, gfx1100 (27B UD-Q4_K_M) | **0.000565 / 98.971 %** |
| after the fix, `--ub 4`, gfx1201 | **-0.000000 / 100.000 %** |
| `test-fusion-gate-beta-multiseq`, extended to `{BF16,1024} {Q8_0,1024} {Q8_0,5120}` x 11 shapes | **33/33 bit-identical, all fused**, on gfx1201 and gfx1100 |

The shipped unit oracle only covered **BF16 at K=1024**; every delivered GDN model runs
`blk.N.ssm_alpha/beta.weight` as **Q8_0 at K=5120**, so the Q8_0 sibling had no oracle at all.  The test now
covers both siblings and the model's real contraction length.

## The visible consequence: the target's greedy text moved

Dense 27B UD-Q4_K_XL, `--spec-type draft-mtp --spec-draft-n-max 3`, 1 GPU gfx1201, a pinned reasoning prompt
(`/tmp`-style template, `-n 1200`), 2 interleaved rounds per arm:

| arm | text | drafts / accepted | tg |
|---|---|---|---|
| r200 (pre-fix), fusion **on** | 4771 chars `sha=0ac05e4cb358` | 1247 / 782 | 61.4 / 61.1 |
| r200 (pre-fix), fusions **off** | 4628 chars `sha=8631f9a3a623` | 1257 / 780 | 58.8 / 58.9 |
| r201 (post-fix), fusion on **and** off | 4628 chars `sha=8631f9a3a623` (identical) | 1257 / 780 (identical) | 61.0 / 61.1 |

So a *default-on* fusion was changing the target's own output, and moving MTP acceptance with it -- the class
both #263 and #265 report.  (The fusion is worth **+3.6 % decode** on that arm: 58.9 -> 61.0 t/s.)

## gfx1100 (the #263 arch): the default path is uniform, the kill-switch arm is not

`test-logits-width-probe P=4096` (row 0 across W=1..8):

| arm | gfx1201 | gfx1100 |
|---|---|---|
| default build | PASS (maxdiff 0) | PASS (maxdiff 0) |
| `GGML_CUDA_FUSE_GATE_BETA_VERIFY=0` | PASS | **FAIL**, W=1 vs W>=2, maxdiff 0.138 (0.000565 at `--ub 4`) |

`GATE_BETA_VERIFY=0 + GGML_CUDA_DISABLE_FUSION=1` PASSes, so the residual is a **W=1-only try-fuse pass that is
impure on RDNA3_0 when the gate/beta fusion does not preempt it** -- i.e. a defect in a kill-switch arm, not in
the shipped default.  The decode arm on gfx1100 agrees: fusion on 710/977 `sha=eca29f334d6a`, off 704/988
`sha=152af1d9feb7`, both unchanged by the softplus fix.  Tracked as `TODO.md` **#130** with the recipe; a
dedicated gfx1100 session owns it.
