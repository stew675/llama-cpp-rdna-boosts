# gfx1151 masked-column sign leak — session record (2026-09-09, halo)

Status: investigation + repro tooling complete; fix in progress in `~/llama.cpp`.

## Problem

Host-side freed-cell KV zeroing (`llama_kv_cache::zero_freed`, gfx1151-gated, block-14
amendment) exists because FA kernels can accumulate masked-out cells' V inexactly:
a fully masked column (P == +0.0) must contribute exactly 0, but on gfx1151 some
accumulation paths leak the *content* (sign) of whatever V the cell last held, so a
freed cell that is only ever read masked still influences the output — the result of a
request depends on what the previous request left in the cache.

Goal: make the kernels exact so the host-side zeroing can be deleted.

## Probe results (isolated kernel matrix, garbage V in fully-masked tail)

kv=1280, nvalid=1025..1152, hsk=256, nh=16, nh_kv=4 (server shapes) unless noted:

| kernel / config | f16 KV | bf16 KV |
|---|---|---|
| HIP VEC (nq=1, hsk<=256, nh=1) | clean | clean |
| HIP TILE (nq=1, hsk=256 GQA) | clean at tested geom | **leaks ~7e-9** (geom-dep) |
| HIP MMA_F16 (prefill nq=32/128) | **leaks ~1e-5..4e-5** | **leaks ~2e-5..6e-5** |
| Vulkan scalar (path=0, e.g. hsk=128) | clean at tested geom | — |
| Vulkan cm1 coopmat (path=1: GQA-fold decode + prefill) | **leaks ~1e-6..1e-5** (geom-dep) | — |

K-only garbage is always clean; the leak comes through V.  Magnitude is
~independent of |V| (V=0.5 vs 60000 gave identical diffs) -> a signed-zero / rounding
artifact of the masked-cell (+0.0 x V) products, not a scaled P*V term.  Geometry
sensitive: 16-block-aligned fully-masked runs are skipped exactly (MASK_OPT
ALL_NEG_INF / bounds); leaks appear in boundary blocks at specific n_valid (e.g.
HIP bf16 TILE leaks at nvalid 1025/1063 but not 1100/1152; Vulkan cm1 at 1063 but
not 1025).

Diagonal probe (fattn-diag, partial columns, live V): Vulkan cm1 f16 leaks
per-element (~1.2e-5), HIP bf16 leaks tiny (~1e-13); HIP f16 clean at tested
geometry.  Partial-column cells hold *live* (deterministic) V, so those leaks are
run-to-run deterministic and out of the freed-cell scope; freed/stale cells only
ever sit in fully-masked columns, so the fix targets fully-masked columns (== the
scope of the host zeroing).

## Key structural facts

- Vulkan decode with GQA folds N=1 -> N = gqa_ratio (4 here), so single-token decode
  runs the **cm1 coopmat** shader (not scalar).  Scalar (path=0) is only for MHA /
  no-GQA small batches.
- Vulkan f16 FA uses SHMEM_STAGING=0 + **direct global V coopMatLoad** when no
  KV_bounds and f16 KV — the shipping decode/prefill case.  Per-column V zeroing is
  only possible on the kvsh-staged path; direct loads need staging for masked
  boundary chunks or another mechanism.
- HIP server decode: f16/bf16 both TILE (hsk=256); prefill MMA_F16 (WMMA).  TILE's
  bf16 PV uses v_dot2_f32_bf16 (packed pairs); f16 uses ALU half2 (exact).
- Validation strategy: fixed kernel build with LLAMA_KV_ZERO_FREED=0 should be
  BIT-IDENTICAL to the current build with zeroing ON (both = exact masked columns);
  and the 16/16 gates must pass zeroing-off on every config that failed.

NOT fixed-zeroOFF == old-zeroON (old was leaky).

### Mechanism discovery (surprising, worth keeping)

The MMA leak is NOT a plain row-level "P=+0 x V!=0" phenomenon:
- Triangular CAUSAL masks: orig is EXACT (causal dump orig==fixed bit-identical
  even with nonzero V in fully-dead rows 128..1024 and garbage in the tail).
- Column-uniform masks (rows >= boundary masked for ALL queries): orig leaks,
  non-monotonically in geometry: nvalid=1279 LEAK, 1275 LEAK, 1270 OK, 1265
  LEAK, 1264 OK, <=1260 OK (probe, K tail = +0). At 1265 the probe (K tail +0)
  leaks but the dump (K tail random) does not; at 1279 both leak.
- Leak is V-only (KGARB=1/VGARB=0 -> OK; VGARB=1 -> LEAK).
So the artifact is a WMMA pairing/geometry subtlety that the simple model does
not capture; the empirical criterion (never feed a fully-dead row's V to the
mma) removes every observed signature and is behavior-neutral where orig was
exact. Real llama.cpp causal prefills (rows beyond each block's position range
fully dead) never exercised the MMA leak - the fix matters for column-like
freed/stale cells and per-seq masks over shared KV cells (batch serving), i.e.
exactly what the host zeroing was guarding.

### Conclusion for the delivery proposal
Every KV-cache type that can reach flash attention on either backend (ROCm:

LLAMA_KV_ZERO_FREED=0, and ON==OFF bit-identical where both were run. The
gfx1151-only host-side zero_freed workaround is redundant across the supported
matrix; non-FA types are structurally safe. Remaining before the block-14
proposal: nothing on this box except writing it up (depth-16384 methodology on
the delivery box is a multi-GPU concern, unaffected by these kernels' numerics).
