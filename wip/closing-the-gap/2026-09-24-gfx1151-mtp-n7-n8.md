# gfx1151 — the `n7`/`n8`/adaptive MTP matrix (§4.4): `0031` closes the W=9 cliff

**Status:** measured on `halo` (gfx1151) 2026-09-24, after [`0031`](patches/0031-gap-closing-WIP-gfx1151-MMVQ-band-policy.patch).
Build: `gap-closing-denseband` (= `gap-closing-final` + `0031`), single gfx1151, ROCm 7.14.
**The `off_both`/dense-off attribution arm confirms the fix is the cause.**

The gfx1201 `2026-09-24` record ([`2026-09-24-mtp-cpu-spin-automatic.md`](2026-09-24-mtp-cpu-spin-automatic.md) §4)
already showed that after `0028` the `n7 >> n8` gap on gfx1201 was the **W=9 MMVQ→MMQ cliff**, not the
acceptance curve.  `gfx1151` is where the original `n8 > n7` was observed, so this is its replication.

## Protocol

`llama-cli`, qwen4exp `IQ4_NL` + `mtp-…-shared-Q8_0.gguf`, single GPU (`HIP_VISIBLE_DEVICES=0`),
`-ngl 99 -fa auto -ctk q8_0 -ctv q8_0 -c 16384 -b/-ub 2048 -n 3000 --seed 42 --temp 0`,
reasoning pinned per axis (`on` for R, `off` for P/C/K/X), `--log-verbosity 4`.  Arms: `none`
(plain), `n7` (`draft-mtp --spec-draft-n-max 7`), `n8` (… 8), `adaptive`
(`draft-mtp-adaptive --spec-draft-n-max 8`, the OP-3 cap), and `n8denseoff`
(the same `n8` with `GGML_CUDA_DISABLE_MMVQ_DENSE_BAND=1` — the `off_both`-style attribution arm).
Prompts: `reasoning.txt` / `code-python.txt` / `recall.txt` / `prose-rdna-boosts.txt` /
`code-reasoning-mixed.txt` (all sha256-pinned in `prompts/README.md`).

## What it says

* **`n_max 8` is no longer dominated on gfx1151.**  With `0031`, `n8` beats `n7` on R (+7 %),
  C (+3.6 %), K (+4.0 %) and P (+7.4 %), and ties on nothing; the **only** axis where `n7` wins is
  **X (phase-switching)**, where the `n8` acceptance drops (0.382 vs 0.457) — a chain that drafts
  too deep wastes work when the workload changes phase.  This is the same shape as gfx1201
  post-`0028` and the opposite of the pre-fix gfx1151 `n7 >> n8`.
* **The `0031` dense band is the cause, not acceptance.**  The `n8denseoff` arm is slower than `n8`
  on every axis (R −19 %, P −9 %, K −7 %, C −5 %, X −2 %) with **acceptance essentially unchanged**
  (R 0.324 vs 0.387, C 0.773 vs 0.769, K 0.955 vs 0.957, P 0.647 vs 0.666, X 0.409 vs 0.382) — the
  cost is the dense MMQ fallback at `n_tokens = 9`, exactly the cliff `0031` widens away.
* **Adaptive is workload-shaped, as designed.**  It wins R (44.2) and X (47.5) by dropping depth on
  low-acceptance / phase-changing content, ties C, and loses to fixed `n8` on K (75.9 vs 78.4) and
  P (54.2 vs 56.5) where the acceptance curve supports a deeper chain.  The tuned bucketed controller
  is working as intended on this model/box; the fixed `n8` is the right arm for predictable content.
* **MTP accelerates on every axis** over plain decode (K +143 %, C +99 %, P +79 %, X +48 %, R +18 %);
  acceptance is healthy everywhere (pos-1 ≥ 0.77), well above the ~0.45 gate.

## Verdict

* `0031` is confirmed end-to-end for MTP: the gfx1151 W=9 verify cliff is gone, and the `n8` /
  adaptive arms are usable again.
* Reporting rule for gfx1151: **`n8` (or adaptive) is the default-cap candidate; `n7` remains the
  phase-switching pick.**  No `n_max` > 8 evidence here.
* The gfx1201 table and this table now agree in shape (absolute t/s differ because gfx1151 is a
  single APU); the earlier gfx1151 `n7 >> n8` was the pre-`0031` dense fallback, now fixed.

## Reproduce

```sh
export HIP_VISIBLE_DEVICES=0 LD_LIBRARY_PATH=/opt/rocm-7.14-gfx1151/lib:$LD_LIBRARY_PATH
BIN=~/llama.cpp/build-rocm/bin/llama-cli        # gap-closing-denseband (0031)
MU=/llm/models/Qwen3.8/Flash-Next/IQ4_NL/Qwen3.8-Flash-Next-IQ4_NL-PROJFIX-00001-of-00009.gguf
MD=/llm/models/Qwen3.8/Flash-Next/IQ4_NL/mtp-Qwen3.8-Flash-Next-shared-Q8_0.gguf
PR=~/llama-cpp-rdna-boosts/prompts
for arm in none n7 n8 adaptive n8denseoff; do
  case $arm in
    none)       SPEC="--spec-type none"; MDARG="";;
    n7)         SPEC="--spec-type draft-mtp --spec-draft-n-max 7"; MDARG="-md $MD";;
    n8)         SPEC="--spec-type draft-mtp --spec-draft-n-max 8"; MDARG="-md $MD";;
    adaptive)   SPEC="--spec-type draft-mtp-adaptive --spec-draft-n-max 8"; MDARG="-md $MD";;
    n8denseoff) SPEC="--spec-type draft-mtp --spec-draft-n-max 8"; MDARG="-md $MD";;
  esac
  [ "$arm" = n8denseoff ] && export GGML_CUDA_DISABLE_MMVQ_DENSE_BAND=1 || unset GGML_CUDA_DISABLE_MMVQ_DENSE_BAND
  $BIN -m "$MU" $MDARG -ngl 99 -fa auto -ctk q8_0 -ctv q8_0 -c 16384 -b 2048 -ub 2048 \
    --seed 42 --temp 0 -n 3000 --single-turn --no-display-prompt --reasoning off $SPEC \
    -f "$PR/prose-rdna-boosts.txt" --log-verbosity 4
done
```
