## 5. PR #27992 / prev-token index - the user's memory (confirmed)

Yes - we rolled our own indexed version. It is captured (0005) and
applies clean. Key nuance from the 08-31 handoff: at 16K ctx the index is
FLAT vs the general scan (683 vs 692 t/s); the win is at 240K ctx (2.7x
decode). The 16K CPU burn that LOOKED like get_prev_tokens was actually
per-ubatch host overhead (graph scheduler + gallocr reserve + the 27.4 GB
ngram GET_ROWS gather spinning 16 OpenMP threads). So for the 16K ITEM B
work, the prev-token index is NOT the limiter; for 240K it matters.

## UPDATE 2026-09-02 (evening): ITEM B latency pass + Q8_0 KV + 128K

### QSA kernel latency work (commits 7b5a94cca, abc4b13ee on qwen4exp)
Phase breakdown (clock64 instrumentation, pp2048, per block of 64 tiles):
- load: 773K cyc (49%) -> 280K (29%)  [smem K/V staging + 8B vector loads]
- score: 563K (35%) -> 270K (28%)    [batched reduce + pair-prefetch K regs]
- soft: 40K (2.5%) unchanged
- vkq: 208K (13%)                     [V staged in smem, unrolled 4x]
Wins applied: cooperative K/V smem staging (1 L2 fetch per tile per block
instead of 12x per-warp), uint2 vector loads on 4B-aligned padded rows,
batched score reduce (all NSTEPS partials in regs, one shuffle tree),
pair-prefetch (2 cells' K into regs before mad chains), VKQ unrolled 4x,
per-cell mask staged with K. VGPR 72->80. 35KB smem (K+V) -> 1 block/CU.
- TILE=16 sub-tiles: WORSE (extra softmax barriers ate the occupancy win)
- double-buffered TILE=16: WORSE (1910-1920 vs 1927)
- 8B (uint2) > 16B (float4): float4 misaligns the odd-padded rows
- "vectorized VKQ" (uint2 reinterp): REGRESSED badly, reverted

### Q8_0 KV support (abc4b13ee)
- QSA kernel now accepts -ctk q8_0 -ctv q8_0: the cooperative load
  dequantizes Q8_0 blocks (d*qs[i] -> F16) into the smem tiles once per
  tile; score/VKQ unchanged. kv2_t smem = half2 for F16+Q8_0, BF16 native.
- Correctness: max logit diff 3.66 vs F16 KV, top-1 11/11 (100%).

### 128K depth REACHED (the reason Q8_0 was needed)
- F16 KV at 128K = 12.9GB (OOM with ub=2048; 3x32GB GPUs have ~1GB
  headroom after model 26.9GB/GPU + 3.75GB compute + hipBLASLt 200MB ws)
- Q8_0 KV = 7.2GB at 128K, fits. ub=512 needed (smaller compute buffers).
- Depth curve (Q8_0 KV, sparse QSA, WMMA off):
    16K: 1930 (F16)  32K: 1845  64K: 1710/1681  128K: 1134 (ub=512)
  dense reference: 1896 (16K) / 1415 (32K) / 995 (64K) / 571 (128K)
  -> sparse wins +2% @16K, +30% @32K, +72% @64K, +98% @128K.
  The sparse advantage compounds with depth - ITEM B thesis confirmed.
