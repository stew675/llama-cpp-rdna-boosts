## UPDATE 2026-09-02 (night): indexer-pipeline depth falloff - fused op + radix tuning

### GGML_OP_INDEXER_TOPK (commits 483f77fae, 9dff5cc4f on qwen4exp)
The indexer materialized the full [n_kv, n_tps] F32 expanded tensor
(512MB at 64K, mirrored on every GPU) per QSA layer just to feed TOP_K:
GET_ROWS 1.4 + CONT 6.78 + F16->F32 mask cast ~1.5 + ADD 2.7 + TOP_K 8.3
= ~21ms/layer. The new fused op computes value[c] = score[cell_blk[c]] +
mask[c] on the fly in each radix pass (src0=score [n_blocks, n_tps,
n_stream] F32, src1=cell_blk [n_kv, n_stream] I32, src2=mask F16/F32,
param k). Output [k, n_tps, 1, n_stream] I32 - same layout the QSA op
consumes, so the downstream reshape disappeared too.

KEY gotchas (both cost real debugging time):
- Do NOT ggml_reshape_3d(kq_mask) per layer as the additive: that
  materializes 13 x 256MB F16 copies at 64K (compute buffer 2040 ->
  4856 MiB, OOM). Pass the raw 4D [n_kv, n_tps, 1, n_stream] mask; the
  size-1 dim is a no-op stride so the kernel's 3D indexing is identical.
- The smem histogram init/accumulate in the radix only zeroed the first
  BLOCK_SIZE bins - latent bug for NBINS > BLOCK_SIZE. Fixed to zero all
  NBINS bins. (An 11-bit radix attempt using this code path faulted;
  RB=11's overlapping bit-10 pass is not worth the risk - reverted.)

Radix tuning: blocks_per_row capped at 8 (was up to 64). Histogram
buffer 134MB -> 16MB at 64K, select pass work 8x less. INDEXER_TOPK at
64K: 10.17 -> 7.61 ms.
