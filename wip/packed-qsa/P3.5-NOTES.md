# Packed-QSA — P3.5 notes (2026-09-15)

**Status:** P3.5 measured.  Verdict: **the packed path cannot win on gfx1201 in the canonical
serving configuration.**  The whole P3 end-to-end conclusion was drawn in the wrong split mode
(`-sm layer`); re-measured under the canonical `-sm tensor` the packed path is *worse*, and the
ceiling even with a free merge descriptor is +0.8 %.  The packed attention kernel itself is at
**parity** with the VEC kernel in the canonical geometry (not 1.35x — that was a layer-split
artifact).  See §4 for the decision.

## 1. The benchmarking-mode error (the central fact)

The P1–P3 record (and the handover's §1.4 scoreboard) used `-sm layer`.  For qwen4exp the canonical
serving config is **`-sm tensor`** and it is dramatically faster:

| config | pp8192 (IQ3_XXS, f16 KV) |
|---|---:|
| `-sm layer` (handover's config) | 874 t/s |
| `-sm tensor`, default ub | 1606 t/s |
| `-sm tensor`, `-b/-ub 2048` | **2289 t/s** |

`-ub 2048` matters again on top of the split: the P1 pack is rebuilt per ubatch over the whole
growing cache, so fewer/larger ubatches reduce the total pack traffic ~3.4x.

The P1 author chose `-sm layer` because the packed path **aborts** under `-sm tensor` (the P1 meta
assertion, §3).  So the campaign was never evaluated in the config that is served.

## 2. Canonical scoreboard (gfx1201, 3x R9700, `-sm tensor -b/-ub 2048`, pp8192)

| arm | pp8192 | vs pure VEC |
|---|---:|---:|
| pure VEC (no pack) | 2289.18 ± 10.32 | — |
| **P1 pack only** (no merge, VEC attn) | 2286.27 ± 12.69 | **−0.1 %** (pack is free) |
| pack + **P2 merge** + VEC attn | 2177.92 ± 8.69 | **−4.9 %** |
| pack + merge + **P3 WMMA** (full) | 2185.97 ± 15.91 | **−4.5 %** |
| pack + merge(no rows kernel) + VEC† | 2307.17 ± 1.24 | +0.8 % |
| pack + merge(no rows kernel) + WMMA† | 2298.97 ± 12.97 | +0.4 % |

† `GGML_CUDA_QSA_MERGE_NOROWS=1` is **incorrect** (see §3) — the row is there only to bound the
upside: with the expensive half of the merge removed the packed path is still only ~break-even, and
the WMMA kernel is ~0.4 % *slower* than VEC.

At ub=512 (`-sm tensor`) the same ordering holds and the full path is −7.2 % (1606 / 1533 / 1490).

**So the entire overhead is the P2 merge descriptor build, and even removing it does not make the
packed path win.**  The P1 pack is free; the P3 kernel adds nothing.

## 3. Root cause: `qsa3_rows_kernel` (merge kernel A)

`rocprofv3 --kernel-trace` on the `pack+merge+VEC` arm (pp4096, ub2048, tensor) — kernel time sums
are inflated ~1.8x by the profiler and are useful for shares only:

| kernel | calls | total | per call | share of all kernels |
|---|---:|---:|---:|---:|
| `flash_attn_qsa<256,f16>` (VEC reference) | 96 | 805.6 ms | 8.39 ms | 8.0 % |
| **`qsa3_rows_kernel`** (merge A) | 96 | **244.5 ms** | **2.55 ms** | **2.4 %** |
| `qsa3_merge_kernel` (merge B) | 96 | 19.6 ms | 0.20 ms | 0.2 % |
| `indexer_topk_*` (all) | — | 87.7 ms | — | 0.9 % |

The merge build (A+B) is ~5 % of the pass end-to-end; **kernel A is 12x kernel B**.  Kernel A walks
all `n_q * ns` index entries to (a) sentinel-normalize, (b) test ascending, (c) rank-sort any
unsorted row.  It is the same O(n_q·ns) pass the attention itself makes, with none of its reuse.

Two facts that constrain the fix:
* **The rows are not always sorted.**  `GGML_CUDA_QSA_MERGE_CHECK=1` reports `rows_sorted=1` at
  ub2048 (it was 0 in the old ub-default runs) — one row in 2048 took the sort path.  Dropping
  kernel A (`GGML_CUDA_QSA_MERGE_NOROWS=1`) makes the descriptor mismatch the host oracle
  (12 fields) and fails the synthetic self-test (8247 mismatches).  So kernel A cannot simply be
  deleted; the ascending assumption has to be established elsewhere (e.g. make the indexer emit
  ascending keys) or the merge made order-agnostic.
* The merge kernel B alone is ~free (+0.8 % arm is within noise of pure VEC), so a *correct* kernel
  A that costs nothing would leave the packed path at ~parity, not ahead.

## 4. Decision

* **P4 (tensor-split support) is feasible and was implemented/validated**: the packed shadows split
  consistently with the K/V kv-head axis (keys axis 3, values axis 2; device1 = head0's blocks,
  device2 = head1's).  The P1 "must be mirrored" assertion was over-conservative; the relaxation in
  `ggml-backend-meta.cpp` is kept.  A/B under `GGML_CUDA_QSA_ATTN_CHECK=1` gives the same
  `rel ≈ 3.9e-5` as layer split.
* **P3.5 does not reach a win on gfx1201 in any measured config.**  The 1.35x op-level figure was a
  `-sm layer` artifact; the canonical geometry puts the kernel at parity and the merge A kernel
  costs ~5 %.  The best-case (free merge A) is +0.8 % over pure VEC.
* Recommendation: **park the packed-QSA campaign for gfx1201.**  If it is continued it must be on
  **gfx1151** (Strix Halo), where the QSA op is ~14 % of the pass and the VEC kernel is the slow
  reference this design was built against — but the ~5 % merge A cost is architecture-independent
  and must be dealt with there too.  Any further gfx1201 kernel tuning (Track B in the old
  handover) cannot pay: with a free merge and a *2x* kernel the ceiling is ~+7 % QSA share × … i.e.
  ~4 % of the pass, and the kernel is currently at 1.0x.

## 5. Levers added this session (all default-off, no delivery impact)

| env | effect |
|---|---|
| `GGML_CUDA_QSA_PACKED_MERGE=0` | build the P1 pack but skip the P2 merge entirely (isolates the pack cost) |
| `GGML_CUDA_QSA_MERGE_NOROWS=1` | skip merge kernel A (and `srow`) — **BREAKS correctness** (rows are occasionally unsorted); diagnostic only |
